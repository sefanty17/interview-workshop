# javaee 章节细节稿

## 第1章 · 开场与自我介绍

风雪的面试间在走廊尽头，门牌上只贴了一张打印纸，四个字：技术一面。

推门进去时，房间比想象中更空。一张长桌，两把椅子，一台合着盖子的笔记本，桌上摆着一只白瓷杯，杯口没有热气。墙角立着一台暖风机，开着，暖风把窗帘吹得轻轻鼓起又落下。窗外的天是阴的，玻璃上蒙着一层薄薄的水汽，像谁潦草地擦过一遍。

面试官坐在靠窗那一侧。蓝色长发，帽檐压得很低，两只有猫耳的轮廓在帽边轻轻动了一下。深蓝色的外套领子立着，袖口露出来一小截苍白的手指，指尖搭在桌沿上，没什么温度的样子。她抬头看过来时，眼睛是很浅的蓝，不带情绪。

「坐。」

钦灵拉开椅子坐下。椅脚刮着地板，声音在安静的房间里格外响。她刚想开口打个招呼，对方先说话了。

「规矩我讲一遍。」风雪把面前那张薄薄的简历往前推了一指的距离，姿势几乎没有变，「一面，四十分钟。你讲，我听。我不问废话，你也别说废话。你要说『精通』可以，那我就顺着这两个字往下挖，挖到你脚下没有东西为止。」

她顿了顿，帽檐下的视线落在钦灵脸上。

「还有一条。你答不上来的，就说答不上来。我最讨厌的不是不会，是拿一堆词把不会包起来。我这人吧——」她抬手把那杯早已不热的茶推到一边，「鼻子很灵，能闻出来哪句话是空的。」

钦灵笑了一下，试图把气氛松一松：「那我尽量说人话。」

「很好。」风雪的耳朵抖了一下，很轻微，「那就从最好讲的地方开始：三分钟，自我介绍。工作经验、会什么、最近在做什么。别看稿，我这儿没有提词器。」

「现在开始。」

钦灵没立刻开口。她低头想了两秒，把手里攥着的笔放下，抬起头。

她讲得不算快。先说学校，说两年前进的公司，说自己现在在一个做履约的平台组，组里四个人，她负责订单履约链路上的状态同步和超时补偿——下单、拆单、仓库回传、发货通知，出了岔子都是她那一块的事。她说这两个月最有分量的一件事是把一个每天早上七点固定出现的对账延迟从二十多分钟压到了两分钟以内，靠的是把一个全表扫描的定时任务拆成了按仓库分片的批处理，中间加了一层幂等表。她讲的时候手偶尔会在桌面上比划一下分片的方向，讲完看了一眼手表，补了一句：

「差不多这样。后面看您想问哪块。」

风雪一直没打断，连坐姿都没换。等房间里的声音落下去，她才把杯子又挪回原处，指尖在杯壁上敲了一下。

「有点意思。」她说，「不过你刚才那三分钟里，『我们』出现了六次，『我』出现了三次。你说你们把对账延迟从二十多分钟压到两分钟，那这二十多分钟里头，哪一部分是你动手拆的，哪一部分是你旁边那三个人弄的？我想听的正是这个分界线在哪。」

钦灵愣了一下。她原以为对方会顺着「分片」这个词往下挖技术，「六次」和「三次」这种量词先一步落到了桌上。

「拆任务是我提的，也是我改的。」她说，「幂等表是另一个同事建的，他只做了索引和唯一约束，字段的语义——比如同一笔拆单回传两次算不算重复——是我们两个吵了一晚上定下来的。压到两分钟以内那次上线，是我在凌晨一点的灰度里盯着看的，中间还回滚过一次。」

「回滚过一次。」风雪重复了这几个字，语调没有起伏，甚至还带着一点让人心里发凉的满意，「好，这比『一次上线很顺利』好听。这个留着，一会儿讲。」

她从桌边拿起一支笔，在简历边上写了一行小字，写得很快，看不出是什么。

「下一问，只答一段。」她把笔放下，两只手叠在膝盖上，「你们那个平台，交付的业务是什么量级的？日均多少单，峰值在什么时候，如果这个数你是猜的，直接说猜的，别给我一个假精确的数字。然后——挑一段**你自己负责的模块**，讲清它在你接手时是什么样，现在是什么样，中间你改动了哪一处，为什么是那一处而不是别处。」

钦灵的手在桌面上轻轻敲了两下，像在心里换算。

「日均三十万单上下，日峰值在上午十点到十一点之间，这个数是从我们的监控面板上看的，不是我估的。大促的时候能到平时的三倍多。」她说，「至于模块——我讲履约状态同步。我接手的时候它是一段一千二百多行的方法，里面七个 if 套着，靠一个 status 字段的数值往下走，从下单到签收一共九种状态，任何一种状态变化都会触发一次全量重算。现在拆成了五个职责分开的类，状态机单独拎出来，配置化。改的就一处：我把状态推进从『谁拿到锁谁算』改成了『事件驱动 + 状态机的合法迁移校验』。为什么是这里——因为那七个 if 里出现过两次把已取消的订单又推回待发货的情况，根子不在 if 写得丑，在于没有一个地方统一说『从 A 能不能到 B』。」

「『两次』。」风雪把这个数字夹了出来，帽檐抬了一点点，露出半只蓝眼睛，「哪两次，什么时候，谁发现的。」

「一次是仓库操作员误操作，一次是我自己写测试的时候构造出来的。」钦灵说，「第一次是我们运维在客服工单里翻出来的，同一个用户被发了两遍货。那之后我做了一次全量的脏数据扫描，扫出来十七笔。」

风雪静了一会儿。窗外的风吹了一下，暖风机的风向歪了，把桌角那张简历掀起了一个小角，她伸手按住，按得很随意。

「三次机会，我给你一次。」她忽然说，「你说你改的是状态机，那我问你一个特别朴素的问题：你把状态机拎出来之后，那个『合法迁移』的规则表，是你们业务方定的，还是你自己看着代码反推出来的？」

房间安静了半秒。

「一半一半。」钦灵说，「业务方给的是文档，文档上有两处自相矛盾——比如『已取消』的订单能不能被重新激活，一处写能，一处写不能。我自己反推的时候按不能处理的，然后拿着这份矛盾去和产品对了半小时，最后定成不能，但单独加了一个『重新下单』的入口。」

风雪的指尖在杯沿上停了一下。

「你倒是肯翻文档。」她说得很轻，像是自言自语，「行，这一问我记下了——不是记你答得好，是记着你没有把那个矛盾藏起来。我这儿很多人讲到这儿就开始绕了。」

她把简历翻了个面，笔帽朝着钦灵点了一下。

「还剩一件事。刚才那一段里，你说你『负责』履约链路上的状态同步和超时补偿。那把你手里的事交出来——如果明天你请假一周，你那个东西会先烂在哪？给我一个具体的场景，不要给我『应该没问题』。」

钦灵想了想，说：「超时补偿的定时任务会先出问题。它判超时的依据是回传时间和我这边的落地时间差，这个阈值现在写死在配置里是十五分钟，而仓库那边在大促的时候会自己调慢。上周就是大促，我们组的同事调整的时候不知道要同步改这个阈值，结果有一批订单被判了超时又重新发了通知，用户手机上收到了两条。如果我不在，这种『改一头忘一头』的耦合还会再出现一次。」

「好。」风雪把杯子端起来，又放下了，好像只是为了让手有地方放，「这个『耦合』两个字，是这一轮唯一一句我觉得你不是在准备过的稿子里念出来的。我很讨厌准备过的稿子，稿子会把你最好看的部分盖住。」

她偏了偏头，帽檐下的影子落到桌面上。

「接下来我会离开自我介绍这块地了。」她说，「你刚才有一句话，我记在本子上了——『一夜之间线程池打满，接口大面积超时』，你们那个平台，是不是也踩过？」

钦灵点头。

「那就讲它。」风雪把笔搁下，两手交叠撑着下巴，眼睛很安静地看过来，「下一题，我不接受概括。我要听那一夜。」

暖风机还在响，窗玻璃上的水汽在慢慢往下流，积成一道细细的水痕。

## 第2章 · 线程池打满的那一夜

风雪没有马上让她开口。她先把那只白瓷杯挪到桌子一角，露出底下一圈被压出来的水印，又把合着的笔记本转了半圈，屏幕朝自己这边。

「这一题我给你两分钟组织，」她说，「但我不要结论，我要过程。你从哪里知道出事的，第一眼看到的是什么数字，接下来按什么顺序做了什么。中间哪一步想岔了，也讲。」

钦灵把两只手叠在膝盖上，掌心有点潮。

「那天是周四。」她说，「晚上八点四十左右。」

「具体点。」风雪没抬头，「你怎么知道的。」

「告警群先响的。两条。一条是履约回调接口的错误率，五分钟窗口从百分之零点二跳到百分之三十七；一条是网关的平均响应时间，从八十毫秒涨到两秒多。」钦灵说，「我刚到家，鞋还没换。第一眼我没去翻应用日志，我先把监控大盘打开了。」

「为什么不先看日志。」

「因为那时候我不知道是哪一段在慢。日志是点上的，大盘是一片的。」钦灵说，「我先看的是三样东西叠在一起：入口 QPS、下游各家的耗时曲线、还有这个服务的线程池活跃数。」

风雪的手指在桌面上敲了一下，很短，像在心里给她盖了一个记号。

「看到什么了。」

「入口 QPS 没掉，还略高一点，说明流量正常进来了，不是被打垮了。下游几个接口的耗时全是平的，没有哪一家突然变慢——这条很关键，它把我第一个猜测劈掉了。」钦灵说，「我一开始认定是某个下游堵住了我们的回调线程。下游的线是平的，那堵的地方就只能在我自己这一头。」

「线程池。」

「活跃线程数顶到了上限，队列在涨，而且是涨得很快的那种涨。」钦灵说，「排队时间从几毫秒爬到八百多毫秒。这个组合出来，我心里就有数了：线程被攥住了。」

风雪把帽檐抬了一点。

「『被攥住了』四个字说得很顺。」她说，「那你告诉我，另外一种情况你怎么排除的——线程不是被卡住，是活太多、慢慢干？这两种在你的大盘上，长得像不像？」

钦灵停了两秒，摇头。

「像。」她说，「说老实话，光看大盘我分不出来。所以第二件事我拉了一份线程快照。快照里四十多个线程停在同一行，栈顶都是回调服务里的同一个方法，不是在等网络，也不是在等数据库连接。四十多个线程堵在同一个点上，那就不是活多。」

风雪「嗯」了一声。

「这一句是到现在为止我最想听见的。」她说，「很多人到这儿就开始背线程池怎么配参数了。你先掏了一份证据出来。行，继续——知道卡在一个锁上，然后。」

「然后我基本能定位到代码了。」钦灵说，「那个方法里有我半年前加的一段：回调进来之后同步刷一次库存快照。加它是因为客服天天喊看不到实时库存。那段逻辑挂在同一个同步链路上，加完压测跑的是低并发，没炸出来。」

「为什么没炸出来。」

「因为低并发的时候那把锁几乎不排队。」她说，「压测我们按单机两百 QPS 跑的，曲线很漂亮。那天晚上单机是六百多。锁持有时间也就一两毫秒，可六百多 QPS 叠上去，队列就排到几秒开外去了。」

「于是线程池就满了。」风雪把话接过去，语气还是平的，「现在讲止血。我不问你后来重构得多漂亮，我问那一晚——你手里有什么，你先动了哪一刀，动了之后多少分钟回了血。」

钦灵说：「我记得很清楚，八点五十二分做的第一个动作。」

「这么快就动手。」风雪说，「没等谁批准？」

「等不了。我先在回调接口上加了一个开关，把同步刷新快照那段整个短路掉，直接返回旧值。这个开关是我加那段逻辑的时候顺手留的，本来是为了灰度回滚用的。」她说，「改完发上去是八点五十七分，错误率在两分钟内掉回到个位数，队列也就散了。」

「那五分钟里下游有没有替你们挡了一下。」风雪问，「比如限流。」

「有。网关那边的同事在八点五十的时候按预案把非核心来源的流量摘了，这是他们的规则，不是我请求的。但如果只有他们那一步，队列还会重新涨回来，因为真正的锁还在。」钦灵说，「我还做了第二件事：把这批回调的任务并发从我们这一侧调低了，代价是那二十分钟里有一批订单的状态更新慢了几秒。我选的是慢，不是错。」

风雪在纸上写了两笔，笔尖按得很实。

「『我选的是慢，不是错。』」她把这句话重复了一遍，「好。那你现在告诉我，第二天你怎么知道这件事真的过去了，而不是被你先藏起来了？」

「快照那条链路，我把它从同步挪到异步之后，专门盯了三天。」钦灵说，「第一天看的是队列有没有积压，第二天看的是快照延迟的 P99，第三天我抽了五百笔订单去对账——按订单号把快照和主库的状态一条一条比过去，比出来两笔快照还是旧的。都是卡在迁移过程中的那一批，属于可以解释的范围内，但我还是把它们记进了工单，让写迁移脚本的同事补了一个重推入口。」

「两笔。」风雪说，「你连两笔都去追了。」

钦灵的耳根有点热。「不是因为负责，是因为那阵子我被客服问怕了。」

风雪嘴角动了一下，很快收住。「这一句倒是老实。那复盘呢。我要的不是一份写给人看的复盘，我要你老实说，这件事里哪一条是你自己的问题——不是『我们团队在流程上』，是你。」

钦灵没有马上答。暖风机忽然停了一下，又嗡地重新转起来，声音比刚才低了些。

「我的问题是，我给压测框的边界太窄了。」她说，「我加那段逻辑的时候，压的是单机两百 QPS，可我明明知道线上单台的高峰能到六百。我当时想的是『反正是个读接口，多花一两毫秒无所谓』——我估的是延迟，没估锁的排队。这是我最该被骂的一处：我拿平均值去替了并发。」

「平均值和并发，差在哪，一句话。」

「平均值把排队藏起来了。」钦灵说，「一场事故往往不是平均慢，是一小段时间里所有人都挤在同一把锁上。你看平均耗时，什么都看不见；你看 P99 和排队深度，那一晚早就写在大盘上了。」

风雪安静地看了她一会儿，那种看法不像是判断对错，更像在称一样东西。

「你前面说，你上线灰度的时候回滚过一次。」她忽然拐了个弯，「那次回滚，跟你后来这段反思有关系吗？」

「没有关系。」钦灵说，「那次回滚是幂等键拼错了，把仓库编号拼进了业务单号里，导致一部分重复回传没被拦住。跟锁没关系，是我那天凌晨脑子不清醒。」

「很好。」风雪把笔搁下，「你要是把两次都揉成『都是我对并发理解不深』，这一题就算白讲了。」

她把椅子往后靠了靠，帽檐抬起来了一点，眼睛在阴天的光里显得更浅。

「我这一问就到这儿。你答上来的部分我觉得你是真做过；没答上来的，是你在那一刻没能把『锁』和『容量』分开想——这不算污点，算你现在的位置。」她顿了顿，「现在我们从夜里回到白天。你刚才讲对账延迟的时候提过一个词，『全表扫描』。那条慢查询是怎么被你们发现的，然后你从它身上往下查到哪一步。」

钦灵抬起眼，像是知道这一章要翻页了。

## 第3章 · 索引、缓存与一次选型的取舍

「那条慢查询，最先是被谁听见的。」风雪把翻过去的简历又压回桌面上，用手指压住一只角，「不是你听见的吧。」

「不是。客服先听见的。」钦灵说，「用户反馈订单列表刷不出来，转圈转到超时。客服那边一天收了十几条，同一个页面，都是翻到第二页、第三页才卡住。我第一反应还以为是前端的问题，去看接口，发现只有带翻页参数的那个查询在慢，第一页永远是好的。」

「第一页永远是好的。」风雪把这句话咬了一下，「你自己说，这句话告诉你什么。」

「告诉我这不是数据库整体扛不住，是我这条 SQL 的某一段在特定参数下换了执行路径。」钦灵说，「我把慢查询日志翻出来，那一句话一条，跑一百七十多毫秒，一天打进来几十万次。我又去看了 rows，扫描行数比结果条数大了三个数量级。」

「那你先做的是加索引，还是先做的别的。」

「先看的执行计划。」钦灵说，「我把三条子句一条一条拆开去 explain。第一版看的时候，key 那一栏写着走了我自己建的那个联合索引，我一开始还以为索引好好的——这里我走了一步岔路，我以为索引选错了字段顺序，就动手调顺序。调完还是慢。」

风雪的耳朵动了一下。「这一句你留着，一会儿有用。先说岔路怎么回头的。」

「我把 explain 的 filtered 和 extra 摊开看，发现索引是进了，但只用了它最左边的那一列，后面的条件全变成了 filter，在回表之后还要一行一行过。」钦灵说，「原因是我那条 SQL 的一个条件上套了函数——我为了让前端好处理，把时间字段外面包了一层格式化函数，等于我在让数据库先算一遍再比。索引上存的原始值，一进函数就没法比了。」

「你知道最让我在意的是哪一句吗。」风雪把杯子推远了一点，「不是那个函数。是你刚才说『走了联合索引，我以为索引好好的』。很多人干到这儿就停手了，手里有个索引名字就心安了。你怎么知道它只在第一列上生效。」

「因为回表次数。」钦灵说，「我加了一个指标，看这个查询每次的回表行数，跟结果集比。比出来二十六倍。二十六倍的意思就是，我读了二十六行，只留一行。这个比一出来，我就知道后面那些条件没有走进索引里。」

「好。」风雪说，「继续。函数那个我不问了，我问更朴素的：你改成什么样了，改完以后怎么保证它不会在下一次迭代里又被人改回去。」

「我把那个函数从条件里挪走了，改成传进来一个区间，从头一天零点到最后一天二十四点。」钦灵说，「另外我补了一条：那一段的查询逻辑收进了单独的 Mapper，我给它写了一条单测，直接用 explain 的结论断言——扫的行数超过一个阈值就红。我们 CI 里有一步会跑它。所以后面谁要往那个条件上加函数，先得把单测弄绿。」

风雪把帽檐往上推了一格，露出两边的眼睛。

「行。」她说，「那我换一个方向问你——你们那个平台，接口前面挂了缓存没有。」

「挂了。Redis。」

「那就有意思了。」风雪把两只手合在一起，指尖对着指尖，「你先答一个不涉你代码的问题：缓存和数据库，我让你保证别人从你这儿读到的数是准的，你怎么兜。」

钦灵停了两秒。

「分两种。」她说，「一种是允许短暂旧值的，一种是读到自己写的必须准的。前一种我做法是：更新库之后删缓存，删掉之后第一次读重新回源；我能接受删完之后到下一次读之间有一个极短的窗口，那个窗口里读到的是库里的新值，只是慢一下。后一种我不走缓存，或者在会话里记住这个人刚写过哪一条，写完之后那一条直接读库。」

「那『删缓存』这一步，你要不要做成同步的。」风雪问，「同步删，就多一次可能失败的调用。」

「要同步删，但不能让它把请求卡住。」钦灵说，「我们的做法是把删缓存放进业务事务提交之后的回调里，失败了重试三次，三次都失败就丢进一张补偿表，由定时任务扫。扫不到的就打日志告警——我不接受『删失败了但没人知道』。」

「如果两个请求同时在改同一条呢。」风雪说得很快。

「谁的事务先提交，谁的缓存就删两遍——一次提交时删，一次在把请求返回之前再删一次。中间隔的那点时间，正好能覆盖掉另一个线程可能回填旧值的窗口。」钦灵说，「这招不好看，但能兜住那个并发写的小口子。」

风雪安静了一小会儿，忽然问：「这个『删两遍』，你是在哪学的。书上、文章上，还是你自己撞出来的。」

钦灵也没躲：「撞出来的。大促之前我们压测的时候，发现一条库存读数在写完之后十几分钟还是旧的，我一开始以为是删缓存失败了，把日志翻了三遍，删都成功了。后来才想明白，是有一个读请求在我删之前就把旧值拿到手里了，删完之后它把旧值又写回缓存。延时双删是我按这个现象自己凑出来的办法。」

「凑出来的说法我很喜欢。」风雪说，「不过我要挑一句：你说间隔『正好能覆盖掉另一个线程可能回填旧值的窗口』。这个正好，是怎么算出来的。」

钦灵沉默了半秒，然后笑了一下：「算不出来。我压测跑出来的经验值，五百毫秒，压测环境跟线上还不完全一样。它的前提是那个读请求去回源的时间比五百毫秒长，明显不成立的时候是会漏的。所以我真正靠的不是这个值，是我还有一条兜底：库存快照的整点全量重建。你说我这句兜底是不是有点土。」

「土。」风雪说，「但比一堆看起来很高级的都没有强。」她把简历翻到最后一面，笔尖悬着，「到最后一题了。你讲一个你自己做过的技术选型，讲清你为什么选它、当时放弃了什么、后来悔不悔。」

钦灵想的时间比前面任何一题都长。

「选型我讲对账延迟那件事里的一个。」她说，「我们那批对账任务原本是一个整点跑的定时任务，一次全表扫描，扫的是当月所有订单，跑完二十多分钟。我拆成按仓库分片的批处理后，还剩下一个选择：这些分片之间用什么调度方式。当时摆了两个：一种是继续用我们原来的调度中心，配一堆 cron 按仓库分开；另一种是接一个消息队列，订单状态变化就往里扔，消费侧按仓库分区，幂等表兜重。」

「你选了哪个。」

「两个都选了。」钦灵说，「这个答得不好，我知道。我按状态的变化走消息队列，按仓库的日终对账继续留着定时任务。当时我的想法很直白：实时的就走实时，一天一次的历史对账本来就不需要实时，硬塞进消息队列只是让链路更复杂。这个判断我到现在还是认的。」

「那你后悔的是什么。」

「我把两套东西的分片规则写成了两份。」钦灵说，「消息队列的分区键是按订单号哈希，定时任务的分片是按仓库编号。这两套规则一开始对得上，因为订单号里带了仓库段位，后来订单号生成了规则变了，仓库段位挪到了另外几位，我没注意到。那段时间里，同一条订单在实时链路和定时链路里被判进不同的片。数据不算错，但排查的时候我花了一整晚去对一个‘应该一样却不一样’的中间结果。」

风雪把笔放下了。

「你后悔的是写成了两份，不是选了两种。」她说，「我想听的就这一句。选型不是站队，没有人能一次选对；能说清自己是在哪一层上亏了，就已经比大部分人强。」

她把那张简历收进桌边的文件夹里，合上，动作很利落。

「到这儿吧。」她说，「我给你一个总评。你在这个房间里坐着的四十分钟，技术上有硬的东西，也有你不知道的地方——线程池那一题，你对『锁』和『容量』没分开想，最后是你自己补上的；索引那题你走了一段岔路，可你手里有工具，会回头。这两点我算你过关。」

「但我觉得你真正的长处不在技术上。」她抬起眼，帽檐下的蓝色比开场时温和一点，「是你答题的时候，肯把不好看的那半句说出来。回滚过一次、库存快照那条兜底土、分片规则写成了两份——这些话说出来的人不多。我说过我这人鼻子很灵，你至少没拿漂亮话盖着自己。」

她起身把笔记本盖上。

「流程我照实说：我这边过了，后面还有人面一轮，结果一周之内通知。别在群里私下去问 HR 进度，那不会更快。」她伸手把暖风机的风向拨回去，窗帘垂落下来，房间里的声音低了一层，「回去路上想一件事——你今天讲的那些事故里，哪一句是你最亏的。想明白了，下一次你就不会在同一块地方再亏一遍。」

钦灵站起来，椅脚又刮了一下地板。她走到门口时，身后传来一句很轻的补充。

「对了。你那个延时双删的五百毫秒，回去别改成八百，去改成压测里能算出来的值。不然某天它会替你说话，说得比你还准。」

门把手是凉的。走廊里的灯已经开了一半，尽头那台暖风机还在响。
