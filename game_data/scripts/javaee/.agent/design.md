# javaee 设计稿

## 大纲

前提与主题: 面向 Java 后端工程师的技术面，考察自我介绍与项目自述的诚实度、并发与 JVM 的排障路径、数据库与缓存的工程判断
主线走向: 从自我介绍切入，抓住玩家自述的「订单履约系统」这条线，先问一夜线程池打满的线上事故，再从那条慢查询问到索引失效与缓存一致性，最后落到一次技术选型的取舍
结局方向: 面试官给出一句总评与「一周内通知」的口径，把「哪一句答得最亏」留给玩家自己回味
预计章节数: 3

## 第1章 · 开场与自我介绍

id: 01
梗概: 面试官先立规矩，再用三分钟自我介绍和「挑一段你自己负责的模块讲」两问，摸清玩家做过什么、哪句话是撑出来的。
登场: 风雪
素材: backgrounds/面试间.webp, musics/安静环境音.mp3
结束方式: linear → 02

## 第2章 · 线程池打满的那一夜

id: 02
梗概: 面试官追问一次线上告警：线程池被打满、接口大面积超时，玩家要讲清从监控、日志到代码的排查路径，以及当晚的止血与后来的复盘。
登场: 风雪
素材: backgrounds/面试间.webp
结束方式: linear → 03

## 第3章 · 索引、缓存与一次选型的取舍

id: 03
梗概: 从上一章那条慢查询引出索引失效，再问缓存与数据库不一致时怎么兜；最后让玩家挑一个自己做过的技术选型讲清为什么，面试官当场给出总评与通知口径。
登场: 风雪
素材: backgrounds/面试间.webp
结束方式: ai_judged
