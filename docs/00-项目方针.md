## 两条铁律

### 一、前端：1:1 复刻

页面布局、组件形态、尺寸数值、间距、动效曲线、交互反馈，**全部照搬 LingChat 对应页面**。

| 允许改 | 不允许改 |
|---|---|
| 文案（游戏 → 面试） | 布局结构、栅格与分栏比例 |
| 数据字段的业务含义 | 组件形态（卡片/列表/面板长什么样） |
| 无对应页面的新增板块（按它现有零件拼装） | 字号、圆角、间距、颜色、动效参数 |

参照基准：`docs/design/01~20`（每页一份，数值均取自 `references/lingchat` 源码）。

### 二、后端：逻辑 1:1 迁移

Rust 的**数据模型、对话链路、事件协议、prompt 组装、符号解析**，逐条搬到 Java，语义不变。

| 照搬 | 说明 |
|---|---|
| 表结构与表关系 | `role / save / line / running_script` → 我们的对应表 |
| 对话生成链路 | 发送 → 组装 → LLM 流式 → 解析 → 落库 → 推送 |
| 事件协议 | 每句一带情绪、末条 `isFinal` |
| 符号解析 | `【情绪】` / `（动作）` 的正则与语义 |
| prompt 组装 | 人设在内、任务在外，顺序不变 |

**不照搬**：Tauri 桌面运行时（进程内状态机、生成锁、事件总线）、280 个命令、lan_sync、桌宠、Live2D、插件、成就、ASR/TTS 声库。

判据：**它是业务逻辑还是桌面壳**。业务逻辑搬，桌面壳丢。

## 数据格式

一律对齐 LingChat：字段名、结构、枚举值、文件组织方式。

LingChat 没有的（面试评分、评测维度），才新增；新增部分沿用它的命名风格与表关系习惯，
并单独标注「本项目扩展」，便于区分来源。

---

## 遇到「LingChat 没有」的需求

**先在 LingChat 里找对应物，找不到才自建。**

判定顺序：

1. 它是不是某个已有功能的变体？（例：面试流程编排 = **剧本引擎**——`story_config.yaml` 定义流程，`Chapters/*.yaml` 定义阶段，`ai_dialogue / input / chapter_end` 事件驱动，`chapter_end` 的 `linear / branching / ai_judged` 就是轮次判断）
2. 它的数据能不能用现有表的字段表达？
3. 都不行，才新建表或组件，并沿用 LingChat 的命名与结构习惯。

自建前必须回答一句：**这个能力在 LingChat 里是用什么实现的**。答不上来，说明还没找够。

| TTS | `SettingsTts` / `VoicePreview` / 对话内播放 | 语音合成 |
| 长期记忆 | `MemoryBank` + `SettingsMemoryDebug` | 记忆调试 |

### 不迁

致谢名单、退出游戏、lan_sync 局域网同步。
（原先按"业务相关性"裁掉的 TTS、思考链、好感度、世界书、场景感知、MemoryBank、
成就、插件、ASR、投屏、换装、Live2D、桌宠，**已全部恢复为迁**。判据改为：
LingChat 实现了的功能这边就要有对应实现，差异只能是技术栈导致的实现方式差异。）

## 已定技术选型

| 项 | 选择 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Tailwind v4 |
| 后端 | Java 17 + Spring Boot 3.3 + Spring Data JPA |
| 数据库 | H2 起步（跑通后切 MySQL，换方言即可） |
| LLM | DeepSeek `deepseek-chat`（OpenAI 兼容） |
| 流式 | SSE，事件语义对齐 `ai:reply` |

## 执行方式

贵模型定方案 + 验收，便宜模型（`deepseek-v4.1-flash`）执行。
规格写到「填空题」粒度：文件 / 行号 / 原样 / 禁区 / 验收标准。
验收不信执行者报告，自己跑构建、实测数值。

### 前端复刻阶段的分工（硬边界）

主线**不直接修改前端代码**，只做四件事：读原版源码 → 写实施规格 → 派 agent 改 → 对照截图与代码逐项判定。

执行方按规格改，改完交三样证据：我们的截图、原版基准、代码逐行对照表。
审查标准见 `docs/01-前端复刻作业规程.md`，进度见 `docs/02-复刻台账.md`。

### 目录结构照搬

组件文件路径、目录分层、文件名与 LingChat 一致（`components/settings/pages/SettingsText.vue`
这类），只增不改名。这样原版任意一个文件都能直接映射到我们的同名文件，审查成本最低。
