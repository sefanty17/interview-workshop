# 前端复刻作业规程

> 适用范围：设置面板 + 自由对话房间。
> 本文件规定**谁做什么、做到什么程度算通过**。与 00-项目方针.md 冲突时以方针为准，与本文冲突时以本文的执行细则为准。

---

## 一、分工（硬性边界）

| 角色 | 能做 | 不能做 |
|---|---|---|
| **主线（审查方）** | 读 LingChat 源码 → 写实施规格 → 派发 agent → 对照截图与代码逐项判定 → 打回 | **不直接修改任何 `.vue` / `.ts` / `.css` 文件** |
| **执行方（agent）** | 按规格改代码、跑 tsc、截图自查、回报 | 不改规格范围外的文件、不新增依赖、不自作主张"优化" |

例外：同一个 agent 对同一文件连续打回 3 次仍不通过时，主线可亲自出手，但必须在台账里记「主线接管 + 原因」，避免变成习惯。

**主线的工作量应几乎全部花在「读原版代码」和「比对」上，而不是写代码上。**

## 三、唯一允许的差异：可见文案

**只有「屏幕上显示的字」可以换成面试场景的说法。除此之外零差异。**

### 3.1 术语映射表（唯一合法替换，不得自行发挥）

| 原版 | 本项目 |
|---|---|
| 设置 | 设置（保留） |
| 角色 / 人物 | 面试官 |
| 玩家 / 我的身份 | 求职者 / 我的简历 |
| 好感度 | 面试印象 |
| 剧本 | 面试剧本 |
| 存档 | 面试存档 |
| 世界书 | 岗位知识库 |
| 场景 | 场景（保留） |
| 游戏 | 面试 |

未列入本表的文案，**默认保持原样**。需要新增替换时先改本表，再改代码。

### 3.2 改文案不等于可以改布局

- 文案变长导致换行、溢出、错位 → **用原版容器尺寸兜住**（`truncate` / `line-clamp` / 固定宽高），不许调字号、不许改间距、不许挪位置。
- 文案替换后必须截图与原版同尺寸叠加比对，文字块占位差异超过 4px 视为不合格。

### 3.3 代码标识符不改

组件名、变量名、CSS class、事件名保持与 LingChat 同名或语义直译。术语映射只作用于模板里的可见字符串。

## 四、禁止事项（"看起来像"式简化）

以下每一条都单独构成打回理由：

| # | 禁止 | 正确做法 |
|---|---|---|
| 1 | 用近似色代替原色值 | 从原版 class 里取出精确色值，一字不改 |
| 2 | 合并或省略子组件（把弹窗内联成展开区） | 弹窗就是弹窗，层级与 teleport 目标一致 |
| 3 | 省略交互状态（hover / active / disabled / 空态 / 加载态 / 错误态） | 原版有几个态就做几个态 |
| 4 | 用 Tailwind 默认间距近似（`p-4` 代替 `p-[18px]`） | 原版写多少 px 就写多少 px |
| 5 | 用 emoji 或图标库替换原图标 | 原版用什么就用什么（含 SVG path） |
| 6 | 动效"差不多就行" | 时长、缓动函数、位移方向、延迟全部对齐 |
| 7 | 用 flex/grid 重排替代原 absolute 定位 | 定位方式不动，否则视觉位置会漂 |
| 8 | 删掉"看起来没用"的装饰层（光晕、噪点、渐变遮罩） | 装饰层是风格主体，一层都不能少 |
| 9 | 把多个设置项折叠成一个"简化版" | 原版几行几列就几行几列 |
| 10 | 自行发明原版没有的空状态文案/占位图 | 原版没有就留空，或按原版同类组件拼 |

## 五、验收证据（每个批次必须交齐三样）

### 5.1 我们的截图
- 全页 1440×900
- 关键元素局部裁切（弹窗、按钮组、卡片）
- 每个交互态各一张（默认 / hover / 展开 / 弹窗打开 / 空态）

### 5.2 原版基准
LingChat 是 Tauri 桌面应用，不强求跑起来。基准按可信度分级：

| 级别 | 来源 | 用途 |
|---|---|---|
| A | 原版 `.vue` 源码里的 class / 内联 style / CSS 变量 | **最终判定依据** |
| B | `docs/design/screenshots/` 里已存的原版截图 | 视觉对照 |
| C | `docs/design/01~20` 里记录的数值 | 快速核对 |

判定以 A 级为准，B/C 只用于发现"整体感觉不对"。

### 5.3 代码对照表

每个组件交一张表，缺表即不验收：

| 原版 | 我们 | 一致性 | 差异说明 |
|---|---|---|---|
| `GameDialog.vue:412` 面板 `linear-gradient(to top, rgba(0,14,39,.7), rgba(0,14,39,.6))` | `InterviewRoomView.vue:88` 同值 | ✅ | — |
| `GameDialog.vue:430` 圆角 `16px` | 我们写 `14px` | ❌ | 已打回 |

## 六、审查判定（六维检查表）

一个组件只有**六维全过**才算通过：

1. **结构**：DOM 层级能一一对应，没有多包一层或少包一层
2. **数值**：字号 / 行高 / 内边距 / 外边距 / 宽高 / 圆角 / 边框 / 阴影 / 透明度 / 色值，逐项对照
3. **状态**：默认、hover、active、disabled、聚焦、空、加载、错误
4. **交互**：点击、展开、弹窗、右键菜单、拖拽、排序、分页、键盘
5. **动效**：`transition` 属性名、时长、缓动、延迟、方向；`@keyframes` 百分比节点
6. **数据**：字段名、结构、枚举值与 LingChat 一致（本项目扩展字段单独标注）

任一维度不通过 → 打回，写明「哪个文件哪一行、原版是什么、我们是什么」，不写"感觉不对"。

## 七、批次与节奏

| 批 | 内容 | 交付物 |

| B1 | 设置面板外壳：`SettingsPanel` + `SettingsNav` | 两个组件 + 三件套证据 |

| B6 | 粒子 11 个 + animations 2 个 + `ScreenshotButton` + `TouchAreas` | 同 |

规则：

- **一次只派一批**，不并行（并行会互相改同一批公共样式，冲突难查）。
- 每批返回后主线先审，通过才派下一批。
- 打回时在原 agent 会话上继续（`SendMessage`），保留上下文，不重开。
- 每批通过后立刻更新台账状态。

## 八、台账

`docs/02-复刻台账.md`，一行一个组件，状态取值：

`待办` → `已派` → `审查中` → `通过` / `打回(n)`

台账是进度的唯一依据。主线口头说"做完了"不算，台账上写 `通过` 才算。

## 九、已知的前置缺口

本轮是**纯前端复刻**，接口不接。以下按原版做视觉与交互，数据用现有 mock 或空态：

- 房间对话内容：仍走本地假数据（S3 才接 DeepSeek）
- 好感度 / 场景 / 记忆 / TTS 的设置项：能改能存 localStorage，不落库
- 成就 / 插件 / 投屏 / ASR：界面照做，功能占位

判据：**界面不许因为是占位就做简化**。占位只在"没有真实数据"这一层，不在"没有界面元素"这一层。
