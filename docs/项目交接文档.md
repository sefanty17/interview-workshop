## 2. 方案要求原文

> 以下为《计算机专业课程设计（期末课设）题目汇编》第 16 题的原文，未做改写。

### 16 AI 模拟面试与能力提升软件（锐捷网络）

**命题方向**：智能计算  
**题目类别**：应用类

#### 背景说明

高校毕业生数量逐年增加，就业竞争日益激烈。大学生虽具备专业技能，但普遍缺乏面试经验、紧张怯场、无法精准展现个人能力、不了解不同岗位的面试要求；传统就业指导多为一对多的讲座或有限的模拟面试，难以提供个性化、沉浸式、可反复练习的指导服务。锐捷网络是行业领先的 ICT 基础设施及行业解决方案提供商，中国网络设备三大供应商之一，在云课堂业务长期实践中关注从学习到就业的全链条人才培养，观察到传统面试准备方式缺乏真实互动场景、难以获得即时客观反馈，已成为影响高质量就业的关键瓶颈，因而提出构建“AI 模拟面试与能力提升平台”。

#### 项目说明

**【问题说明】**

1. 缺乏真实感练习——难以获得贴近企业真实流程的模拟面试机会；
2. 反馈滞后且主观——依赖人工指导，反馈不即时、难以量化，且受指导者主观经验影响大；
3. 岗位针对性弱——不同技术岗位（如后端开发、前端工程师、算法工程师）的面试侧重点差异巨大；
4. 综合能力评估不足——面试不仅考察技术知识，还考察沟通表达、逻辑思维、应变能力等软实力。

本项目旨在开发一个“面向计算机相关专业学生的 AI 模拟面试与能力提升平台”，核心是构建一个能够模拟不同技术岗位面试场景、并进行多维度智能评估与反馈的 AI 教练。平台应能：岗位化情景模拟（针对至少两种计算机专业岗位构建专属面试题库和评估模型）；多模态互动面试（通过语音、文本与 AI 面试官进行多轮沉浸式对话，AI 能根据学生的回答进行动态追问）；能力评估与深度反馈（对技术回答正确性、语言表达逻辑性、沟通能力、知识掌握深度等多维度量化评分，生成详细评估报告与改进建议）；个性化提升路径（根据历次模拟面试记录分析能力短板，智能推荐学习资源，形成“练习-评估-提升”闭环）。

**【用户期望】**

1. 学生可以获得随时可用的、个性化的面试教练，降低面试焦虑；
2. 学生可以通过反复练习和即时、客观的反馈，快速提升面试技巧；
3. 学生可以清晰了解目标岗位的能力要求，针对性补齐短板。

#### 任务要求

**【开发说明】**

1. 岗位化题库与知识库构建：构建至少针对两种计算机专业岗位（需明确定义，如 Java 后端、Web 前端、Python 算法）的面试题库，包含技术知识、项目经历深挖、场景题、行为题等；建立相关知识库（岗位核心技术栈、常见面试考点、优秀回答范例等），作为 RAG 的基础。
2. 多模态交互式模拟面试界面：提供语音和文字两种输入方式，实现与 AI 面试官的自然、流畅对话；AI 面试官需具备多轮对话能力，能根据学生回答的关键词进行智能追问，并控制面试节奏。
3. 面试表现多维度分析模块：内容分析（利用大模型深度分析回答的技术正确性、知识深度、逻辑严谨性、与岗位的匹配度）；表达分析（集成语音识别与情感分析技术，评估语速、清晰度、自信度等）；综合报告生成（结构化评估报告，含各维度得分、亮点与不足分析、具体改进建议）。
4. 能力提升反馈：根据评估结果为学生推荐提升建议和练习计划；记录面试历史，可视化展示能力成长曲线。

**【技术要求与指标】**

1. 大模型应用：至少使用一个大语言模型作为核心，用于对话管理、内容理解和报告生成；
2. 多模态处理：需实现语音识别与文本/内容的综合分析；
3. 岗位针对性：系统需清晰演示针对不同岗位的差异化面试题目与评估标准；
4. 实用性和创新性：界面友好，交互流程符合用户习惯，反馈结果对学生有实际指导意义。

**【开发工具与数据接口】** 无限制，自行选择。

## 3. 需求拆解

### 3.1 必做（硬性）

| 编号 | 要求 | 落地要点 |
| --- | --- | --- |
| R1 | 岗位化题库与知识库 | 至少 2 个岗位（Java 后端、Web 前端）；技术/项目/场景/行为题；题库 + 岗位知识库 + 优秀回答，RAG 可检索 |
| R2 | 多模态交互面试 | 语音 + 文字；多轮；根据回答关键词追问；控制节奏 |
| R3 | 多维度分析 | 内容：正确性、深度、逻辑、岗位匹配；表达：语速、清晰度、自信度；结构化报告 |
| R4 | 能力提升闭环 | 改进建议、练习计划、历史记录、成长曲线 |
| R5 | 技术底线 | 至少一个大模型；语音识别；岗位差异化；界面友好 |

### 3.2 隐含必须做

- 面试状态机：开场 → 自我介绍 → 抽题 → 回答 → 追问 → 下一题 → 结束 → 报告；
- 题库管理（增删改查、标签、难度、参考答案、评分要点）；
- 会话、录音/转写、报告存储；
- 评分 rubric 与一致性控制；
- 录音授权与隐私提示。

### 3.3 本期不做（明确边界）

- 数字人/视频分析/声学情绪识别；
- 实时打断、多人面试；
- 平台（钉钉/超星）嵌入；
- 教师端班级管理（列为后续）。

## 4. 产品设计

### 4.1 页面与路由

| 路由 | 页面 | 状态 |
| --- | --- | --- |
| `/` | 首页：开始面试、继续面试、面试记录、面试设置、剧本编辑器、创意工坊 | 可用，视觉待重做 |
| `/interview` | 面试房间 | 可用（mock） |
| `/settings` | 面试设置 | 可用（UI） |
| `/records` | 面试记录 | 可用（mock） |
| `/report/:id` | 面试报告 | 可用（mock） |
| `/script-editor` | 剧本编辑器 | 可用 |
| `/workshop` | 创意工坊 | 占位 |

### 4.2 设置页：人设 × 知识注入

- **面试官人设**：严格技术面（林工）、温和 HR（周老师）、压力面（陈总）、技术专家（顾博）；
- 可调：称呼、语气、开场白、追问强度、语速、语音开关；
- **知识点注入**：岗位（Java 后端 / Web 前端）、知识点多选、题量、时长、追问深度；
- 后续接入：人设 → system prompt；知识点 → RAG 检索范围 + 选题 + 评分权重。

### 4.3 面试流程

```
开场 → 自我介绍 → 题目 1 → 回答 → 追问（0–2 层）→ 题目 2 …
     → 结束 → 评分 → 报告 → 练习计划
```

### 4.4 评分与报告

| 维度 | 权重 |
| --- | --- |
| 技术正确性 | 30% |
| 知识深度 | 20% |
| 逻辑严谨性 | 20% |
| 岗位匹配度 | 15% |
| 表达 | 15% |

表达指标：语速（字/分钟）、长停顿、口头语、ASR 置信度、文本确定性词。

## 5. 技术方案

### 5.1 技术栈

| 部分 | 语言/技术 |
| --- | --- |
| 前端 | TypeScript + Vue 3 + Vite + ECharts |
| 音频采集 | TypeScript（Web Audio / AudioWorklet，WAV 16k） |
| 后端 | Java 17 + Spring Boot 3.3 |
| Agent | Java + Spring AI 1.0（ChatClient + `@Tool`） |
| RAG | Java + Spring AI Embedding + pgvector |
| 文档解析 | Apache Tika + PDFBox + POI |
| ASR | Java 调阿里/讯飞/Whisper HTTP API |
| TTS | 浏览器 `speechSynthesis`（MVP）/ 云 TTS（P1） |
| 数据库 | MySQL 8 + Redis 7 + PostgreSQL 16 + pgvector |
| 部署 | Docker Compose + Nginx |

### 5.2 关键决策

- 运行时只用 **Java + TypeScript**；Python 只做离线题库/评测脚本；
- 不引 Python 侧车、不引 Rust、不做本地大模型；
- 向量检索用 pgvector，不上 Elasticsearch；
- 语音优先云 ASR，降低部署成本。

### 5.3 计划中的数据表

`job_role`、`knowledge_point`、`question`、`question_tag`、`interview_session`、`interview_turn`、`evaluation`、`report`、`script`、`script_step`、`user`。

### 10.2 运行

```bash
cd frontend
npm install
npm run dev        # http://127.0.0.1:5173
npm run build
```

Windows 可双击 `frontend/start-demo.bat`。

### 10.3 参考项目用途

- `references/lingchat`：首页、设置面板、对话房间的视觉与交互参考；
- `references/deeptutor`：RAG 管线、Agent loop、评分/练习设计的参考；
- 两者都不直接作为交付代码。
