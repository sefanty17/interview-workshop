## 1. 数据层：六张表

结构与 LingChat 的对应关系：

| LingChat | 本项目 | 说明 |
| --- | --- | --- |
| `role` | `interviewer` | 角色卡 |
| `save` + `running_script` | `interview_session` | 场次 + 运行状态（当前章节 / 事件序号 / 变量） |
| `line` | `interview_message` | 台词 |
| `story_config.yaml` | `interview_script` | 面试流程模板 |
| `Chapters/*.yaml` | `interview_chapter` | 流程阶段（events 数组） |
| —（LingChat 把身份写在角色卡里） | `user_profile` | 用户身份，本项目归一化 |

DDL：`data/schema/schema-h2.sql`　种子：`data/seed/*.sql`

### 1.1 运行状态怎么存

`interview_session` 三个字段承担 `running_script` 的职责：

| 字段 | 对应 | 用途 |
| --- | --- | --- |
| `current_chapter` | `running_script.current_chapter` | 走到哪一章 |
| `event_sequence` | `running_script.event_sequence` | 章内走到第几个事件 |
| `variable_info` | `running_script.variable_info` | JSON，存分支变量（答对数、剩余时间等） |

刷新页面时按这三个字段续跑，不重放已完成的章节。

### 1.2 现有种子

| script | 面试官 | 岗位 | 章节 | 事件 |
| --- | --- | --- | --- | --- |
| `java-strict` | 风雪 | java | 6 | 28 |
| `frontend-standard` | 钦灵 | frontend | 5 | 20 |
| `python-pressure` | 松子 | python | 5 | 20 |
| `java-expert` | DeepSeek | java | 5 | 20 |

生成脚本 `scripts/gen_script_seed.py`，校验 `scripts/verify_seed_sql.py`。

## 2. 剧本引擎

### 2.1 事件类型

LingChat 支持 18 种，本项目用其中 6 种：

| 事件 | 字段 | 作用 |
| --- | --- | --- |
| `narration` | `text` | 旁白，不占对话轮次 |
| `ai_dialogue` | `character`, `prompt` | 让 LLM 按 prompt 说一句（提问/追问/反馈） |
| `input` | `hint` | 阻塞，等候选人回答 |
| `free_dialogue` | `switch`, `maxRounds`, `endLine` | 放开若干轮自由对话后收尾 |
| `modify_character` | `characterId`, `emotion` | 强制切立绘（如「进入施压阶段」切到严肃） |
| `chapter_end` | 见 2.2 | 阶段结束，决定下一章 |

其余 12 种（`background` / `music` / `sound` / `ambient` / `present_pic` / `background_effect` / `choice` / `dialog` / `player` / `set_variable` / `achievement` / `script_end`）解析器一并支持，但种子数据暂不使用。

### 2.2 chapter_end 的三种跳转

出处：`script_engine/events/chapter_end_event.rs`

| end_type | 行为 | 面试场景用法 |
| --- | --- | --- |
| `linear` | 直接跳 `next_chapter` | 固定流程，如 破冰 → 基础 |
| `branching` | 遍历 `options[]`，按 `condition` 对 `variable_info` 求值，取第一个命中的 `next`；都不命中取 `default` | 按答对题数决定加分题还是直接进下一阶段 |
| `ai_judged` | 把对话上下文与 `options[].name` 交给 LLM，让它选一个 | 主观判断：答得是否扎实、要不要加压 |

`ai_judged` 的 LLM 不可用时必须终止，不回落默认分支（同 LingChat）。

### 2.3 流程推进

```
读 session.current_chapter + event_sequence
  → 取 chapter.events[event_sequence]
     ├ ai_dialogue → 组装 prompt → LLM 流式 → 推送 → seq++
     ├ input       → 停下等用户提交
     ├ chapter_end → 计算下一章 → 切章 → event_sequence = 0
     └ 其他        → 执行副作用 → seq++
  → 全部事件走完 → status = finished → 触发评分
```

这张图就是后端 `InterviewEngine` 的全部职责，不需要别的状态机。

## 3. Prompt 组装

### 3.1 结构：人设在内、任务在外

原样导入的人设是「占卜师风雪」「狼娘钦灵」，它们不会主动面试。
所以人设整段保留，外面套一层任务与格式约束：

```
[system]
# 角色设定（原文，勿改）
{interviewer.persona_prompt}

# 你现在的工作
你正在主持一场 {岗位} 的技术面试。保持上面角色的语气与性格，
但职责是面试官：按考点提问、听出含糊就追问、每题给一句简短反馈。

# 候选人
{user_profile 摘要}

# 本场规则
考点：{kps}　题数：{total}　追问上限：{depth}　时限：{limit} 分钟

# 当前动作
{chapter.events[seq].prompt  ← 剧本里写的那句指令}

# 输出格式（硬性）
每句以【情绪】开头，情绪只能取：正常 平静 高兴 兴奋 害羞 心动 紧张 慌张 担心
害怕 惊讶 疑惑 无奈 生气 厌恶 伤心 羞耻 自信 认真 调皮
不要输出 <> 内容，不要输出日语。

[history] 最近 N 轮 interview_message
[user] 本次回答
```

顺序不可颠倒：风雪的人设 5042 字，任务指令放前面会被淹没。

### 3.2 符号解析

出处：`ai_service/message_system/processor.rs`

| 符号 | 正则 | 处理 |
| --- | --- | --- |
| `【情绪】` | `【([^】]*)】([^【】]*)` | 切段：情绪 → 切立绘，正文 → 气泡 |
| `（动作）` | `（([^）]*)）` | 存入 `action` 列 |
| `<日语>` | `<([^>]*)>` | 本项目禁用，解析时丢弃 |

情绪必须折叠到 20 个枚举：

```
原始标签 → aliases 折叠（emotions.json 82 条）→ 枚举命中？→ 是：切图
                                                  └ 否：回落「正常」
```

原卡范例里出现过的 `冷淡 / 盯着 / 正经` 都由 aliases 覆盖。

### 3.3 流式协议

`POST /api/sessions/{id}/messages` 返回 `text/event-stream`，事件语义对齐 `ai:reply`：

```
event: reply
data: {"seq":1,"emotion":"紧张","originalTag":"冷淡","text":"这个……我先想想。","isFinal":false}

event: reply
data: {"seq":2,"emotion":"认真","text":"好，那我换个问法。","isFinal":true}

event: done
data: {"messageId":42}
```

每句一带情绪、末条 `isFinal`，前端收到就切立绘 + 上气泡。

## 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/interviewers` | 面试官列表 |
| GET | `/api/interviewers/{code}` | 详情（含完整人设） |
| GET | `/api/scripts?job=java` | 剧本列表 |
| GET | `/api/scripts/{code}` | 剧本 + 全部章节 |
| GET | `/api/profile` / PUT | 用户身份 |
| POST | `/api/sessions` | 开始面试（选面试官 + 剧本 + 考点）→ 返回首章首个 AI 台词 |
| GET | `/api/sessions/{id}` | 场次详情（含消息，用于刷新续跑） |
| POST | `/api/sessions/{id}/messages` | 提交回答 → SSE 流式回复 |
| POST | `/api/sessions/{id}/advance` | 推进到下一事件（无用户输入时，如旁白） |
| POST | `/api/sessions/{id}/finish` | 结束 → 触发评分 |
| GET | `/api/sessions?status=finished` | 面试记录 |

## 6. 阶段与验收

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| S2 | Spring Boot 骨架 + 6 张表 + GET 接口 | `curl /api/interviewers` 返回 4 条；`/api/scripts/java-strict` 含 6 章 |
| S3 | 剧本引擎 + LLM 流式 + 符号解析 | `curl -N` 逐事件收到 `reply`；`【发疯】` 回落「正常」不报错；断网降级不白屏 |
| S4 | 前端接真流式 + 立绘层 | 点开始 → 立绘出现 → 逐句冒出 → 情绪变则立绘变 → 刷新能续跑 |
| S5 | 评分与记录 | 结束后写入 `score`，记录页可见 |

S3 的三个必测项：情绪枚举命中率、`ai_judged` 跳转正确性、刷新续跑不重放。
