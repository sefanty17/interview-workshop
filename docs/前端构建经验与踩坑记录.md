## 2. 踩坑记录（按严重度排序）

### 坑 1（P0）：未分层 CSS 压掉 Tailwind 工具类

**现象**：nav 按钮字号 14px（应 16px）、字重 400（应 700）、激活字色白色
（应 #79d9ff）、菜单 Maoken 字体不生效、胶囊钮 12px 变 14px——五六处 ✗ 的
**同一根因**。

**原理**：本项目 styles/ 下有一套旧的普通 CSS（base.css/menu.css/tokens.css，
无 @layer）。CSS 规范里**未分层规则的优先级高于任何 @layer 内的规则**，而
Tailwind v4 的工具类全在 `@layer utilities`。于是旧 CSS 里哪怕一句
`button { font: inherit }` 都能覆盖 `text-base font-bold text-[#79d9ff]`。

**修法**：删掉旧 reset（`font: inherit; color: inherit`）与被替代的旧组件规则
（menu.css 的 `.start-item` 全套）。**教训：往旧项目引入 Tailwind 时，第一件事
是 grep 旧 CSS 里所有能命中新组件选择器的规则**（本例是 `.start-item` 与
`button` 元素选择器），先清场再施工。

### 坑 2（P0）：translate 独立属性与 transform 叠加，立绘飞出屏幕

**现象**：首页鼠标一动，立绘整体消失——rect.x 从 0 跳到 -727，且移出后不恢复。

**原理**：Tailwind v4 的 `-translate-x-1/2 -translate-y-1/2` 不再生成
`transform: translate(-50%,-50%)`，而是生成独立属性 `translate: -50% -50%`。
视差 JS 又写内联 `style.transform = "translate(calc(-50% + dx), …)"`——
**两个属性同时生效、各算各的 -50%，位移加倍**。

**修法**：JS 改写同一个独立属性 `el.style.translate = "calc(-50% + dx) calc(-50% + dy)"`，
离开时 `"-50% -50%"`。同属性覆盖，不会叠加。

**通用教训**：Tailwind v4 中位移/缩放/旋转全部走 `translate`/`scale`/`rotate`
独立属性。任何「JS 操作带 Tailwind 位移类的元素」的场景，先想清楚写到哪个属性上；
调试时四个属性都要读。

### 坑 3（P0）：令牌名撞车——`rounded-lg` 不是 8px

**现象**：nav 按钮圆角 22px，应为 8px。

**原理**：旧 tokens.css 定义 `--radius-lg: 22px`，而 Tailwind v4 的
`rounded-lg` 恰好解析到这个令牌（v4 会读取 `--radius-*` 命名空间的用户令牌）。
两个体系对 `-lg` 的语义完全不同。

**修法**：本次最小修复——新组件不用 `rounded-lg`，写死 `rounded-[8px]`。
**根治方案**（未做）：迁移完成后给两套令牌改名隔离（如旧令牌加 `-old` 前缀），
或全量迁到 Tailwind 后删旧 tokens。

### 坑 4（P1）：全屏覆盖层吞掉兄弟元素的事件

**现象**：右上角 Logo hover/点击完全无响应，`elementFromPoint` 命中的是
全屏菜单容器（同为 z-[5]，但 DOM 靠后）。

**修法**：Logo 提到 `z-[6]`；全屏容器 `pointer-events-none` + 内部交互元素
`pointer-events-auto`。**连带坑**：事件绑在被 `pointer-events-none` 的容器上
就不触发了——视差的 mousemove 必须绑在真正接收事件的根元素上。这一连锁是
修复时新引入的，第二轮才发现。**教训：改 pointer-events 时，同步检查同元素上
绑定的所有事件监听**。

### 坑 5（P2）：媒体查询里的残留

主样式表的 `.start-item` 删干净后，`@media` 块内还有 3 条 `.start-item` 覆盖
（字号/padding），继续压工具类。**教训：删旧规则要连媒体查询一起 grep**：
`grep -n "选择器名" 全部样式文件`，而不是只删主定义。

### 坑 6（流程）：Escape 关不掉 Vue 弹窗

验收脚本里用 `page.keyboard.press("Escape")` 关详情弹窗——失败超时，因为
弹窗根本没监听键盘事件（LingChat 原版也没监听）。脚本先点了弹窗外的遮罩
才继续。**教训：写验收脚本前先确认交互方式，别假设有键盘快捷键**。

## 3. 已验证的技术配方（下轮直接抄）

### 3.1 素材与字体

- 素材源：`references/lingchat/src/assets/images/`（background2.png、alona.png）、
  `references/lingchat/public/fonts/MaokenAssortedSans.woff2`
- 字体放 `frontend/public/fonts/`，`@font-face` 里用绝对路径 `/fonts/…`，
  `font-display: swap`
- 图片素材放 `frontend/src/assets/images/`，组件里 `import url from "…png"`
  （Vite 会带 hash 打包，比 public 直引更可控）
- 注意：alona.png 是**宽幅场景图**（2560×1446，含右下角水印），不是透明立绘
  抠图；若要 LingChat 那种「人物浮在背景上」的效果需换素材

### 3.2 Tailwind v4 接入（已完成，勿重复）

- `npm i -D tailwindcss @tailwindcss/vite` → vite.config.ts plugins 加
  `tailwindcss()` → 新建 `src/styles/lingchat.css`（首行 `@import "tailwindcss";`，
  内容含字体/滚动条/glass-effect/glass-input/btn-big）→ main.ts 里在**旧样式
  之后** import（让 lingchat.css 的规则后声明）
- 无需 tailwind.config；v4 零配置，主题令牌写 CSS 变量即可
