# MySQL 索引与慢查询优化

## B+ 树为什么适合做索引

InnoDB 的索引结构是 B+ 树。相比 B 树，B+ 树的非叶子节点只存键不存数据，所以同样大小的页能放更多键，树更矮（千万级数据一般三到四层），磁盘 IO 次数更少；叶子节点用双向链表串起来，范围查询只要顺着链表扫，不用回到根节点。

一次查询大致是：根节点常驻内存，往下两到三次页读取，最后一次读叶子页拿到主键或整行。

聚簇索引（Clustered Index）指索引与数据存在一起，InnoDB 的主键索引就是聚簇索引，叶子节点直接存整行。二级索引的叶子节点存的是主键值，所以通过二级索引查非索引列需要「回表」再查一次聚簇索引。

这也是为什么推荐用自增主键：随机主键（如 UUID）插入会导致页分裂与随机 IO，自增主键总是追加到最右侧，页利用率高。

## 索引失效的常见场景

最左前缀原则：联合索引 (a, b, c) 能命中 a、a+b、a+b+c，不能命中 b、c、b+c。范围查询之后的列用不上索引（a 用了范围，b 就失效）。

隐式类型转换：字段是 varchar 但传了数字，MySQL 会对字段做函数转换，索引失效。反过来字段是 int 传字符串一般没事。

在索引列上做运算或函数：where date(create_time) = '2026-01-01' 会让索引失效，应改成范围查询 create_time >= '2026-01-01' and create_time < '2026-01-02'。

前导通配的 like：like '%abc' 失效，like 'abc%' 有效。要前缀模糊又想要索引，只能用全文索引或者额外维护反转字段。

or 连接的条件里有一侧没索引，整体可能退化成全表扫描。

使用 != 、not in、is not null 时优化器可能放弃索引（取决于选择性）。

## 执行计划怎么读

explain 的关键列：type（访问类型）、key（实际用的索引）、rows（预估扫描行数）、filtered（过滤比例）、Extra（额外信息）。

type 从好到坏：system > const > eq_ref > ref > range > index > ALL。看到 ALL 就是全表扫描，看到 index 是全索引扫描，都要处理。

Extra 里出现 Using filesort 说明排序没走索引，出现 Using temporary 说明用了临时表（常见于 group by 或 distinct），这两个都是性能杀手。

Using index 是好消息，表示覆盖索引，不需要回表。

explain analyze（MySQL 8.0.18+）会给出实际执行时间与行数，比 explain 的预估值可靠得多。

## 慢查询的定位与优化

开启慢查询日志：slow_query_log = ON，long_query_time 设为 0.5 到 1 秒，用 pt-query-digest 或 mysqldumpslow 汇总出 top SQL。

优化顺序：先看是不是缺索引 → 再看索引是否失效 → 再看能不能用覆盖索引消除回表 → 再看能不能改 SQL 减少扫描（分解大查询、去掉不必要的排序）→ 最后才考虑分库分表。

深分页是经典问题：limit 1000000, 20 会扫描 100 万行再丢弃。优化方式有两种：一是延迟关联，先用覆盖索引查出主键再 join 回原表；二是记录上次的最大 id，用 where id > lastId limit 20（游标分页），要求业务能接受。

索引不是越多越好：每个索引都会拖慢写入，占用空间，还会让优化器选错。单表索引一般控制在五个以内，联合索引注意区分度高的列放前面。

## 事务隔离级别与锁

四种隔离级别：读未提交（脏读）、读已提交（不可重复读）、可重复读（幻读，InnoDB 默认）、串行化。

InnoDB 的可重复读靠 MVCC 实现：每行有两个隐藏列（事务 id、回滚指针），读的时候根据 Read View 判断该版本是否可见。快照读（普通 select）走 MVCC 不加锁，当前读（select for update、update、delete）加锁。

幻读在可重复读下用间隙锁（Gap Lock）+ 临键锁（Next-Key Lock）解决。间隙锁锁的是索引之间的空隙，所以如果查询条件没走索引，会锁全表的所有间隙，等于表锁——这是线上锁表事故的常见原因。

死锁排查：show engine innodb status 看 LATEST DETECTED DEADLOCK，里面有两个事务持有的锁与等待的锁。降低死锁概率的手段：固定加锁顺序、缩短事务、给唯一键冲突用 insert on duplicate key update 而不是先查后插。
