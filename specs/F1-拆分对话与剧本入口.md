## 二、后端改动（6 处）

### B1 · `backend/src/main/resources/application.yml`

改：
```yaml
server:
  port: 8080
```
为：
```yaml
server:
  address: 127.0.0.1
  port: 8080
```

**不做的**：本地 token 鉴权。理由写进代码注释即可：绑回环后局域网不可达；同机同用户进程能读 token 文件，token 无防护力；而浏览器侧 JSON 请求已被 CORS 预检拦截。收益低、改动面大（所有前端请求都要改）。

### B2 · `ChatController.java` 改回自由对话

- 构造器改为注入 `ChatService`（保留 `InterviewEngine` 仅用于 `ensureExists` 的 404 前置检查）
- `send()` 方法体改为：
```java
@PostMapping(value = "/{id}/messages", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter send(@PathVariable Long id, @RequestBody SendMessageRequest request) {
    engine.ensureExists(id);
    String text = request == null || request.text() == null ? "" : request.text();
    return chatService.processMessage(id, text);
}
```
- **删掉** `EngineExecutor`、`SseEventSink` 相关的这套调用（`ScriptPlayController` 会用）
- 类注释更新：说明本接口对应原版 `send_chat_message`，剧本输入走 `ScriptPlayController`

### B3 · 新建 `api/ScriptPlayController.java`

四个端点，全部 `@RequestMapping("/api/sessions")`：

| 方法 | 路径 | Body | 返回 |
|---|---|---|---|
| POST | `/{id}/script/start` | `{"scriptCode":"..."}` | SSE |
| POST | `/{id}/script/stop` | 无 | `{"ok":true}` |
| POST | `/{id}/script/input` | `{"text":"..."}` | SSE |
| POST | `/{id}/script/choice` | `{"choice":"..."}` | SSE |

行为定义：

**`/script/start`**
1. `engine.ensureExists(id)`
2. 按 `scriptCode` 查 `interview_script`，找不到 → 400「剧本不存在：{code}」
3. 写 session：`script_id` = 该剧本 id，`event_sequence` = 0，`variable_info` = `{}`（清空）
4. 调 `engine.runFromStart(id, sink)`（新增方法，见 B4）
5. SSE 返回开场事件序列

**`/script/stop`**
1. `script_id` = null，`variable_info` = `{}`，`event_sequence` = 0
2. `status` 保持 `running`（回到自由对话）
3. 返回 `{"ok":true}`

**`/script/input` / `/script/choice`**
- 都调 `engine.submitAndRun(id, text, sink)`，区别只在 choice 版本**强制走 choice 分支**（见 B4）
- 异常透传为 SSE `ai:error` 事件（与 `ChatController` 现有处理一致）

### B4 · `InterviewEngine` 三处改动

**B4-1 · 新增 `runFromStart`**
```java
/** 对应原版 start_script：从章节首事件开始跑。 */
public void runFromStart(Long sessionId, EventSink sink) { run(sessionId, sink); }
```
若 `run` 不是 `public`，改为 `public`（或加此包装方法）。

**B4-2 · `submitAndRun` 补拒绝语义**

现有结构（`:237-261`）改为：

```java
public void submitAndRun(Long sessionId, String text, EventSink sink) {
    submitAndRun(sessionId, text, sink, false);
}

public void submitAndRun(Long sessionId, String text, EventSink sink, boolean forceChoice) {
    InterviewSession session = load(sessionId);
    if (!STATUS_RUNNING.equals(session.getStatus())) { sink.finished(); return; }
    ObjectNode vars = readVars(session);
    String input = text == null ? "" : text;

    JsonNode pendingChoice = vars.get(ChoiceEvent.PENDING_KEY);
    boolean hasChoice = pendingChoice != null && pendingChoice.isObject();
    boolean allowFree = hasChoice && pendingChoice.path(ChoiceEvent.ALLOW_FREE_KEY).asBoolean(false);

    // 原版 script.rs:231-236 —— 选项挂起且不接受自由输入 → 拒绝，不消费
    if (hasChoice && !allowFree && !forceChoice) {
        throw new ScriptInputRejectedException("当前的选项不接受自由输入，请点击一个选项");
    }
    if (hasChoice && (allowFree || forceChoice)) {
        resumeChoice(session, vars, sink, input);
        return;
    }

    JsonNode free = vars.get(FreeDialogueEvent.VAR_KEY);
    boolean inFree = free != null && free.isObject() && free.path("switch").asBoolean(false);

    // 原版 script.rs:244 —— 没有等待输入的事件 → 拒绝，不落库
    if (!inFree && !vars.path(AWAITING_INPUT_KEY).asBoolean(false)) {
        throw new ScriptInputRejectedException("当前没有等待输入的脚本事件");
    }

    if (inFree) {
        vars.put(AWAITING_INPUT_KEY, false);
        persistVars(session, vars);
        freeDialogueTurn(session, vars, sink, input);
        return;
    }

    vars.put(AWAITING_INPUT_KEY, false);
    persistVars(session, vars);
    saveUserMessage(session, input);
    run(sessionId, sink);
}
```

新增常量：`AWAITING_INPUT_KEY = "awaitingInput"`（`variable_info` 里的布尔标记）

**B4-3 · 维护 `awaitingInput` 标记（只有两处写入点）**

- `run(sessionId, sink)` **方法开头**：把 `variable_info.awaitingInput` 置 `false` 并持久化
- `InputEvent.execute` 与 `FreeDialogueEvent.execute` 执行到位时：沿 `EngineContext` 把 `variable_info.awaitingInput` 置 `true` 并持久化
  - `EngineContext` 已持有 `vars`（`ObjectNode`），直接 `vars.put("awaitingInput", true)`；持久化用引擎现有的写回方法（与 `ChoiceEvent` 写 `pendingChoice` 同一个方式，照抄即可）

新增异常类 `engine/ScriptInputRejectedException.java`（`extends RuntimeException`），Controller 层捕获 → `sink.error(msg)` + 400 语义（SSE 里发 `ai:error`）。

### B5 · `ChatService.createSession` 解绑剧本

`:143-147` 改为：`scriptCode == null` 时 **`script = null`**（不再 `findScript`）。
删掉 `findScript(jobId, interviewerId)` 方法（无其他调用者，改前先 grep 确认）。

`:134` 的 `mode` 读取与 `:154` 的 title 拼接：title 改为 `interviewer.getName() + " · " + jobId`（去掉 mode）。

### B6 · `dto/CreateSessionRequest.java`

删掉 `mode` 字段（record 参数同步删）。全仓 grep `mode()` 确认无残留调用。
