# S-2+3 · 配置键归位 + 消灭假开关（合并批次）

> 基线 `2191860`。目标：让每个配置键要么真被消费、要么明确标注「仅存值/本项目扩展」，不允许出现「能改能存但不生效」的假开关。

---

## 一、背景事实（已核实）

| 事实 | 证据 |
|---|---|
| `audio.volume_character` 后端注册了，但**前端 `SettingsSound.vue` 用的是自己的 `characterVolume`（localStorage），完全没读这个 key** | `SettingsSound.vue:342` |
| 原版**没有任何 `AUDIO_*` 配置常量**，音量全在前端 localStorage | 原版 `config/keys.rs` 无 audio 组 |
| `llm.top_p` 进了配置树（前端能调能存），但 `LlmOptions` 只有 `(model, temperature, maxTokens, timeoutSeconds)` 四个字段，**请求体里没有 top_p** | `LlmOptions.java:17` |
| 原版 `llm.model` / `llm.temperature` / `llm.top_p` 运行时**不读全局 key**，真正来源是 provider 级配置 | `provider_config.rs:112-113` |
| `display.font_family` / `display.font_size` 原版没有（原版字号是 `cast.dialog_font_size`） | 原版 `keys.rs` display 组只有两项 |

---

## 二、改动

### A1 · 删 `audio.volume_character`

1. `config/ConfigKey.java`：删 `AUDIO_VOLUME_CHARACTER` 常量
2. `config/ConfigService.java`：删该键的 `intSetting(...)` 注册
3. `ConfigService` 的树映射（`TREE_SPEC`）：`features` 下的 `audio` 子分类整个删掉（删完这个子类就空了，不留空壳）
4. 全仓 grep 确认无残留引用
5. `ConfigServiceTest` / `SettingsControllerTest` 里若有断言 18 项 / 5 子类，相应改成 **17 项 / 4 子类**

> 音量不迁后端是**与原版一致**（原版就在前端），不是丢功能。

### A2 · `display.font_family` / `display.font_size` 标扩展

`ConfigService.java` 里这两项的 `extension` 参数 `false` → `true`，`description` 追加：

> 「本项目扩展：原版字号属投屏模块 `cast.dialog_font_size`，本项目不迁投屏故自建」

### A3 · `llm.model` / `llm.temperature` / `llm.top_p` 标简化实现

三处 `description` 追加一句：

> 「简化实现：原版运行时改读 provider 级配置（`provider_config.rs:112`），全局 key 仅作默认值；本项目未做 provider 表」

`extension` 保持 `false`（这三个 key 原版确实存在）。

### A4 · `LlmOptions` 补 topP

`llm/LlmOptions.java`：

```java
public record LlmOptions(String model, double temperature, double topP, int maxTokens, int timeoutSeconds) {
    public static LlmOptions from(ConfigService config) {
        return new LlmOptions(
                config.get(ConfigKey.LLM_MODEL),
                config.getDouble(ConfigKey.LLM_TEMPERATURE),
                config.getDouble(ConfigKey.LLM_TOP_P),
                config.getInt(ConfigKey.LLM_MAX_TOKENS),
                config.getInt(ConfigKey.LLM_TIMEOUT_SECS));
    }
}
```

`llm/LlmClient.buildRequest(...)` 在 `body.put("temperature", ...)` 旁加：

```java
body.put("top_p", options.topP());
```

- 日志行把 `topP` 也打出来
- 所有 `new LlmOptions(...)` 的调用点（测试里可能用 4 参构造）跟着改

### A5 · 建「key → 消费点」清单

`config/ConfigService.java` 加一个静态集合：

```java
/**
 * 有真实消费点的配置键（改这些键会影响运行行为）。
 * 新增配置项时必须同步维护：要么加进这里，要么 extension=true，
 * 要么 description 里写明「仅存值」——三者必有其一，由 ConfigServiceTest 守卫。
 */
static final Set<String> CONSUMED_KEYS = Set.of(
        ConfigKey.LLM_MODEL,            // LlmOptions.from → 请求体 model
        ConfigKey.LLM_TEMPERATURE,      // LlmOptions.from → 请求体 temperature
        ConfigKey.LLM_TOP_P,            // LlmOptions.from → 请求体 top_p
        ConfigKey.LLM_MAX_TOKENS,       // LlmOptions.from → 请求体 max_tokens
        ConfigKey.LLM_TIMEOUT_SECS,     // LlmOptions.from → HttpRequest timeout
        ConfigKey.CHAT_REPLY_COUNT,     // ChatTuning → PromptAssembler
        ConfigKey.CHAT_MERGE_THRESHOLD  // ChatTuning → SentenceSplitter
);
```

并在 `config/package-info.java`（没有就新建）里写一份同样的清单，注明每个键的消费文件。

剩余 10 项的处理：
- `llm.chat_provider_id` / `llm.enable_thinking` / `features.enable_time_sense` / `features.enable_emotion_classifier` / `display.font_family` / `display.font_size` → `description` 里已有的补「仅存值」三字（font_* 已标扩展，可不加）
- `chat.merge_delay_ms` / `chat.text_speed` / `chat.auto_advance_ms` / `chat.inline_action` → `description` 追加「仅存值：消费端在前端」

### A6 · 单测守卫

`config/ConfigServiceTest` 加一个用例：

```java
@Test
void 每个配置键都必须有消费点或明确标注() {
    for (ConfigSetting s : ConfigService.allSettings()) {   // 没有这个方法就加一个包级可见的访问器
        boolean ok = ConfigService.CONSUMED_KEYS.contains(s.key())
                || s.extension()
                || s.description().contains("仅存值");
        assertTrue(ok, "配置键既无消费点也未标注：" + s.key());
    }
}
```

**反向验证**：临时往注册表里加一个裸键（不改任何标注），跑该测试必须失败；确认后删掉临时键。
