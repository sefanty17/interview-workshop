## 1. 存储映射（技术栈差异，必须写进注释）

| 原版 | 本项目 |
|---|---|
| `story_config.yaml` | `interview_script` 一行 |
| `Chapters/<id>.yaml` | `interview_chapter` 一行（`code` = 章节 id） |
| 章节 YAML 的 `name:` | `interview_chapter.name` |
| 章节 YAML 的 `events:` | `interview_chapter.events`（JSON 数组 CLOB） |
| 章节 YAML 的其余顶层键（`extra`） | **无对应列**，本批丢弃；请求体里的 `extra` 字段忽略 |
| 覆盖前留 `<原名>.bak` | 写入前把旧 `events` 存进新列 `events_backup` |
| 写临时文件 → `rename` | `@Transactional` 单条 UPDATE |

`key` 一律等于 `interview_script.code`，`chapterId` 一律等于 `interview_chapter.code`。

### 1.1 DDL 改动

`backend/src/main/resources/schema-h2.sql`：

1. `CREATE TABLE IF NOT EXISTS interview_chapter` 块里，`events` 下一行插入：
```sql

2. 文件末尾（或该表 DDL 之后）追加幂等补列语句，兼容已存在的库：

## 3. `ScriptSchemaCatalog.java` —— 17 事件 × 14 FieldKind

**这是整个编辑器的地基。所有表单、下拉、校验都从这里取字段。写错一个 key，前端对应表单就空。**

### 3.1 结构约定

- 输出 JSON 的字段名**用 camelCase**（`typeKey` / `assetKind` / `optionLabels` / `defaultDesc`），与 `schema.rs` 的 `#[serde(rename_all = "camelCase")]` 一致。
- `kind` 的值**用 snake_case**，与 `#[serde(rename_all = "snake_case")]` 一致：`text` / `textarea` / `number` / `bool` / `select` / `character` / `emotion` / `chapter` / `asset` / `choice_options` / `branch_options` / `var_options` / `condition` / `deprecated`。
- 可选字段为 `null` 或空 list 时**不输出**（原版 `skip_serializing_if`）。在 `FieldSpecView` 类上加 `@JsonInclude(JsonInclude.Include.NON_EMPTY)`。
- 事件 `fields` 的顺序**必须与 `schema.rs` 完全一致**，前端表单按这个顺序渲染。

### 3.2 完整实现（照抄，不要自己重排、不要"优化"）

            this.label = label;
            this.kind = kind;

            this.required = true;
            return this;
        }

        FieldBuilder hint(String h) {
            this.hint = h;
            return this;
        }

        FieldBuilder placeholder(String p) {
            this.placeholder = p;
            return this;
        }

        FieldBuilder defaultDesc(String d) {
            this.defaultDesc = d;
            return this;
        }

        FieldBuilder options(String... opts) {
            this.options = List.of(opts);
            return this;
        }

        FieldBuilder options(List<String> opts) {
            this.options = List.copyOf(opts);
            return this;
        }

        FieldBuilder optionLabels(String... labels) {
            this.optionLabels = List.of(labels);
            return this;
        }

        FieldBuilder assetKind(String k) {
            this.assetKind = k;
            return this;
        }

        FieldBuilder disabled(String why) {
            this.enabled = false;
            this.hint = why;
            return this;
        }

        FieldSpecView build() {
            return new FieldSpecView(key, label, kind, required, assetKind, options,

        }
    }

## 6. `ScriptEditorController.java`

`@RestController @RequestMapping("/api/editor")`。所有错误响应沿用现有 `ScriptController` 的 `{error, message}` 形状（`ResponseEntity<Object>`）。

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/schema` | — | `ScriptSchemaView` |
| GET | `/scripts` | — | `List<EditorScriptPackage>` |
| GET | `/scripts/{key}` | — | `EditorScriptDetail` |
| GET | `/scripts/{key}/chapters/{chapterId}` | — | `EditorChapterContent` |
| PUT | `/scripts/{key}/chapters/{chapterId}` | `EditorWriteChapterRequest` | `204` |
| POST | `/scripts/{key}/chapters` | `EditorCreateChapterRequest` | `EditorChapterContent`（201） |
| DELETE | `/scripts/{key}/chapters/{chapterId}` | — | `204` |
| PUT | `/scripts/{key}/config` | `EditorWriteConfigRequest` | `204` |

`chapterId` 可能含 `/`（如 `Intro/main`）→ 用 `@GetMapping("/scripts/{key}/chapters/{chapterId:.+}")` 这类写法**不要**用，Spring 6 里路径变量默认不吃 `/`。改成把章节 id 作为查询参数：`GET/PUT/DELETE /scripts/{key}/chapter?id=Intro/main`。

**最终路径定为**（避免路径变量吞斜杠的坑）：
```

GET    /api/editor/scripts/{key}
GET    /api/editor/scripts/{key}/chapter?id=<chapterId>
PUT    /api/editor/scripts/{key}/chapter?id=<chapterId>

## 7. `ScriptEditorService.java`

构造函数注入：`InterviewScriptRepository`、`InterviewChapterRepository`，以及
`@Value("${app.import.asset-target:../frontend/public/backgrounds/scripts}") String assetTarget`（与 `ScriptController` 同一个属性，素材落点必须一致）。

### 7.1 `listScripts()`
`scriptRepository.findAllByOrderByOrderNumAsc()` → 逐个 `chapterRepository.findByScriptIdOrderByOrderNumAsc(id).size()`。
`loadedByEngine` = `Boolean.TRUE.equals(script.getEnabled())`。

### 7.2 `readScript(String key)`
按 `code` 找剧本，找不到抛 `EditorNotFoundException`（`RuntimeException`，controller 转 404）。
- `storyConfig`：见 5.2。
- `chapters`：每个 chapter 解析 `events` 求 `eventCount`（解析失败按 0），`id=code`、`name=name`、`group` 规则见 5.3。**按 `order_num` 升序**。
- `assets`：见 7.5。

### 7.3 `readChapter(key, chapterId)`
`chapterRepository.findByScriptIdAndCode(scriptId, chapterId)`（**需要新增这个查询方法**到 `InterviewChapterRepository`）→ 解析 `events` 为 `List<JsonNode>`。
解析失败抛 `EditorBadRequestException("events 不是合法 JSON 数组: " + 原因)`。

### 7.4 `writeChapter(key, chapterId, req)`
`@Transactional`，步骤严格按序：
1. 定位 chapter 行，找不到 → `EditorNotFoundException`。
2. 校验 `req.events()` 非 null。**允许空数组**（原版允许把章节清空，校验器会报 `chapter.no_events`）。
3. 序列化新 events：`ObjectMapper.writeValueAsString(req.events())`。
   - 序列化前先做一次「每个元素必须是对象且必须有非空 `type`」的检查，不满足 → `EditorBadRequestException("第 N 个事件缺少 type")`。这是原版 `event.missing_type` / `event.not_a_map` 的**写入前置**，不是校验器的替代。
4. 覆盖前备份：`chap.setEventsBackup(chap.getEvents())`。
5. `chap.setEvents(json)`；`req.name()` 非 null 时 `chap.setName(req.name().trim().isEmpty() ? chapterId : req.name().trim())`（原版 `ChapterDoc.name` 为 `Option<String>`，空串等价于不写；我们列非空，空串回落成章节 id）。
6. `chapterRepository.save(chap)`。

**不更新 `order_num`**（新建章节时才排）。

### 7.5 `assetIndex(String key)`
扫 `<assetTarget>/<key>/` 这一层（导入器就是扁平落盘的，见 `ScriptYamlImporter.publishAssets`）：
- `background` = 该目录下扩展名属于 `png/jpg/jpeg/webp/gif/bmp` 的文件名，升序；
- `pic` = 同 `background`（本项目没有独立 `Assets/Pics/`，共用一份）；
- `music` / `sound` / `ambient` = 空 list（本项目导入器只搬背景图；**在 javadoc 里写明这是导入器范围限制，不是编辑器 bug**）。

目录不存在 → 全部空 list，不报错。

### 7.6 `createChapter(key, req)`
1. `chapterId` 非空白；按 `/` 分段，每段过一遍 `sanitizeSegment`（禁 `/ \ : * ? " < > |`、禁 `.`/`..`、禁空白段）→ 不合法 `EditorBadRequestException`。
2. 已存在同 code → `EditorBadRequestException("章节已存在: '" + id + "'")`（原版同文案）。
3. 初始 events **固定为**（原版同款，否则一保存就报「缺少章节结束」）：
```json
[{"type":"chapter_end","end_type":"linear","next_chapter":"end"}]
```
4. `name`：去空白后为空则用 `chapterId`。
5. `orderNum` = 该剧本现有章节数 + 1。
6. 保存后返回 `EditorChapterContent`。

### 7.7 `deleteChapter(key, chapterId)`
找不到 → 404。直接 `delete`。**不做引用检查**（原版 `editor_delete_chapter` 也不做，留给校验器报 `graph.missing_target`）。

### 7.8 `writeConfig(key, req)`
只接受这些键（其余忽略）：`script_name`、`description`、`recommand_start`、`intro_chapter`、`job_code`、`level`、`company_style`、`script_settings`。
- `script_settings` 若是对象 → 序列化成 JSON 字符串存列；若是字符串 → 原样存。
- `script_name` 去空白后为空 → `EditorBadRequestException("剧本名不能为空")`。
- `intro_chapter` 指向的章节不存在 → **不拒绝**（原版也不拒绝，留给校验器报 `config.intro_missing`）。
