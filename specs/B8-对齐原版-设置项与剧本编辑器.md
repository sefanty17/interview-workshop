## 〇、修改原则（先看这一节，后面所有取舍都按它）

1. **原版有的，结构、命名、字段名一律照搬**，包括 `Category` / `Subcategory` / `ConfigSetting` 这三个类型名和 `type` 的取值字符串。
2. **原版没有的，不造。** 已经造出来的（标了 `extension=true` 的 7 项），保留但不伪装成原版功能，说明里必须写「本项目扩展」。
3. **原版「存了不用」的，我们也存了不用**，这叫一致；原版「真消费」的，我们必须有的消费点，**不允许出现假开关**（能改、能存、不生效）。
4. **原版放前端的，就留在前端。** 原版一大批「设置」本来就在 localStorage（音量、打字速度、合并阈值），不是后端权威，不要抄成后端配置。
5. **校验/范围信息的位置照原版**：原版 `ConfigSetting` 只有 4 个字段，范围写在 `description` 文案里 + 后端硬编码校验。我们多加的 `min/max/options` 字段属于扩展，保留但不作为「原版结构」宣称。
6. **不追求 key 数量对齐**（110 个），只追求**同语义的 key 同名同义**。依赖未迁模块的 key（cast.\* / agent.\* / god_agent.\* / tts.\* / translate.\*）不提前造。
7. **编辑器按原版目录重建**：`panels / tabs / flow / fields / modals / preview / agent` 七个目录、26 个文件、文件名一致。现有 876 行 `ScriptEditorView.vue` 拆解而不是继续加功能。

## 六点五、自由对话入口：必须改（独立批次 F-1）

### 原版事实：两套独立接口，没有 mode 概念

| 系统 | 命令（`api/chat.rs` / `api/script.rs`） |
|---|---|
| 自由对话 | `send_chat_message(text)` → `dispatch_chat_turn()` → `message_system` 生成器 |
| 剧本 | `start_script(script_name)` / `stop_script()` / `script_submit_input(input)` / `script_submit_choice(choice)` |

两套**共用 `line` 台词表**，唯一区别是有没有 `running_script`。剧本模式下用户的输入是「投递到 `script_channels.input_tx`」，不是同步处理。

### 行为差异（这是真 bug，不只是结构问题）

`script.rs:217-244`，没有 input 事件在等时：

```rust
if channels.choice_tx.is_some() {
    return Err("当前的选项不接受自由输入，请点击一个选项");
}
Err("当前没有等待输入的脚本事件")
```

**原版直接拒绝、不消费输入。我们全盘接受**：`submitAndRun` 无论有没有人等着，都落库 + `run()` 继续推进。后果是剧本节奏被打乱，用户可在任意时刻插话。

### 我们的偏差

| # | 问题 | 现状 |
|---|---|---|
| F1 | `mode` 参数是死的 | `ChatService.java:134` 读出来后只在 `:154` 拼进 title，**无任何逻辑读它** |
| F2 | 一个接口扛两套语义 | `POST /messages` → `submitAndRun` 三岔分流 |
| F3 | 没有 `start_script` / `stop_script` 对应物 | 建会话时 `findScript()` 就绑死了剧本 |
| F4 | 缺拒绝语义 | 没等着也放行 |

### 修法

| 动作 | 目标 |
|---|---|
| 1 | `POST /{id}/messages` **只做自由对话**：走 `ChatService` → 生成器，不碰引擎 |
| 2 | 新增 `POST /{id}/script/start`（body: `scriptCode`）→ 绑 `script_id` + 初始化 `event_sequence` |
| 3 | 新增 `POST /{id}/script/stop` |
| 4 | 新增 `POST /{id}/script/input`：承接原 `submitAndRun` 的三岔（pendingChoice / freeDialogue / 推进） |
| 5 | 新增 `POST /{id}/script/choice`：显式选项提交，与 input 分开 |
| 6 | `submitAndRun` 补拒绝语义：无事件等待时返回 400 + 原版文案 |
| 7 | 删 `mode` 参数（或保留但仅作 title 展示，并在注释里写明「无逻辑作用」） |
| 8 | 前端 `chat.ts` 拆 `sendMessage`（自由）/ `submitScriptInput` / `submitScriptChoice` / `startScript` / `stopScript`；`InterviewRoomView` 按「当前是否在剧本中」选择 |

**验收**：剧本模式下在无 input 事件等待时提交文本，必须返回 400「当前没有等待输入的脚本事件」，且台词不落库。

### 遗留 2：`execute_command` 的前置条件

智豪的判断：本项目是**用户部署在本地**的外置服务，不是云服务，跑 shell 就是跑用户自己的 shell，所以风险接近桌面应用。

这个判断在「纯本地 + 单用户」前提下成立，但**当前项目状态让这个前提不成立**：

| 事实 | 现状 | 后果 |
|---|---|---|
| 监听地址 | `application.yml` 只有 `server.port: 8080`，**没有 `server.address`** → Spring Boot 默认绑 `0.0.0.0` | 同一 Wi-Fi 下任何设备都能访问 |
| 鉴权 | 无 Spring Security、无 token、无 session | 谁连上谁用 |
| CORS | `WebConfig.java` 白名单 `localhost:5173` | **只约束浏览器读取响应，不阻止请求发出**；`curl` / 任何本机程序完全不受约束 |

**因此迁移 `execute_command` 之前，必须先做两件事：**

```
1. application.yml 加 server.address: 127.0.0.1     ← 只绑本机回环
2. 加一个本地启动 token（前端 dev 时由 vite 注入或后端日志打印），所有 /api/** 校验
```
