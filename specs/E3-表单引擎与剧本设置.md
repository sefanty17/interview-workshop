### 4.2 新 action

```ts
/** 改一个事件的某个字段。空串 / undefined 表示「删掉这个键」（引擎的「不设置」语义） */
export function setEventField(index: number, key: string, value: unknown) {
  const ch = store.chapter;
  if (!ch || !ch.events[index]) return;
  pushUndo();
  const ev = ch.events[index];
  if (value === "" || value === undefined) delete ev[key];
  else ev[key] = value;
  markDirty();
}

/** 整体替换一个事件（切换事件类型时用） */
export function replaceEvent(index: number, next: ScriptEventData) { ... }

/** 保存剧本设置（storyConfig） */
export async function saveStoryConfig(config: StoryConfig) {
  const key = scriptKey.value;
  if (!key) return;
  store.saving = true;
  try {
    await writeConfig(key, config);
    // 后端只回 204，本地把 detail.storyConfig 合并更新；chapters 里 intro 之类的引用不改
    if (store.detail) store.detail.storyConfig = { ...store.detail.storyConfig, ...config };
    store.dirty = false;
    store.lastSavedAt = Date.now();
  } catch (e) {
    await notifyError("保存剧本设置失败", e);
  } finally {
    store.saving = false;
  }
}
```

> `setEventField` 里 **`value === ""` 要删键**，这是原版 `patch()` 的核心语义（`CompositeField.vue:421-427`）。写成 `ev[key] = ""` 会让引擎把空串当成一个真实值，`field.required_missing` 之类的校验结果就跟作者看到的表单不一致了。

### 4.3 `store.variables` 的命名冲突

`store` 是 reactive 对象，`computed` 是独立导出。原版代码里写 `store.variables`（Pinia 把 getters 挂在 store 上）。我们做不到同名，所以：

**改写时把原版的 `store.variables` → `variables.value`（在 script 里）/ `variables`（在模板里，computed 自动解包）**。

同理 `store.characterOptions` → `characterOptions`、`store.chapterOptions` → `chapterOptions`、`store.assets` → `assets`、`store.globalAssets` → `globalAssets`。

**这四个替换在五个 .vue 文件里都要做，漏一个就 `vue-tsc` 报错。**

## 5. FieldRow 的两处裁剪

### 5.1 素材字段（`field.kind === 'asset'`）

原版是「下拉 + 导入到剧本 + 导入到全局」三个控件，靠 Tauri 文件对话框。本项目：
- 保留**下拉**（选项来自 `assets[assetKind]`）；
- **删掉两个导入按钮**，改成一句灰字提示：`素材需要在「素材」页导入（E5 开放）`；
- `assetOptions.length === 0` 时显示 `这个剧本还没有素材。素材可以在「素材」页导入。`（黄字，保留原样色）。
- `globalOnly` 相关逻辑整段删除（没有全局素材）。
- `pickAsset` / `store.uploadAsset` / `@tauri-apps/plugin-dialog` 全部删除。

### 5.2 服装字段（`field.key === 'clothes'`）

原版候选来自「剧本 NPC 的 avatar 子目录 + 全局角色服装」。本项目后端 `characters` 恒空数组（E1 的取舍），所以候选只有 `default` 一项。

处理：保留下拉结构（E5 补 characters 后自动生效），但**当候选只有 `default` 时**显示一句灰字：`暂无服装目录，先在剧本里建角色`. 逻辑照原版写，`store.detail?.characters.find(...)` 拿不到就是空数组，不加特判。

### 5.3 `field.kind === 'deprecated' || !field.enabled`

原版渲染 disabled input。保留。**但要注意**：`chapter_end` 的 `next` 字段 `enabled=false` 且 `kind="deprecated"`，原版这里 `:value="asText"` —— 当 `next` 不存在时显示空 input，视觉上是一个空的禁用框。照抄即可。

### 8.3 FieldRow / CompositeField 的验证

本批 FieldRow 只在 ConfigTab 的 `storyConfigFields` 里用到（4 个字段，kind 分别是 text / textarea / text / chapter），**覆盖不到 composite 和 condition**。

所以必须补一个**临时验证页**（验收后删除）：`frontend/src/views/_E3Probe.vue`，挂一个临时路由 `/e3-probe`，用 `FieldRow` 渲染 `chapter_end` 事件的 5 个字段 + `choices` 事件的 2 个字段，数据用内存里的假事件：

```ts
const probeEvent = ref<ScriptEventData>({
  type: "chapter_end", end_type: "branching",
  options: [{ condition: "flag == yes", next: "basic" }, { default: true, next: "close" }],
});
```

断言：
- `end_type` 是下拉，三个选项；
- `next_chapter` 是下拉且含「剧本结束」；
- `options` 渲染出**分支编辑器**（不是选项编辑器）：两行，第一行有「如果 / 跳到 / 兜底 / ✕」，第二行有 `兜底` 勾选态；
- `next` 是禁用输入框；
- 把 `end_type` 改成 `ai_judged` → 分支编辑器的「如果」行消失，出现「AI 识别名」输入框；
- 再验 `choices`：`options` 渲染出**选项编辑器**，「＋ 添加选项」按钮、每行有「追加玩家台词 / 设置变量 / 触发条件」三行添加区。
- 点「＋ 触发条件」→ 出现 `变量名` 输入 + 运算符下拉（为真/等于/不等于）+ 值输入。
- 点「＋ 设置变量」→ 出现 `变量名` + 运算符（设为/加上/减去）+ 类型（文本/数字/真假/随机整数）+ 值。

截图存 `screenshots/e3/`（至少 4 张：剧本设置页、分支编辑器、AI 判定模式、选项编辑器）。

**验收后删掉 `_E3Probe.vue` 和临时路由。**
