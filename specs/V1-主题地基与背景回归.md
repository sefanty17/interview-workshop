导致全项目 135 处 `bg-brand/*`、`border-brand/*`、`text-brand` 工具类**静默失效**

## 7. 补丁回退（机械替换）

全项目约 105 处 `text-[var(--accent-color)]` / `bg-[var(--accent-color)]` /
`border-[var(--accent-color)]` 任意值写法，回退成 Tailwind 原生 brand 类。

替换规则（`--color-brand: var(--accent-color)` 已在 @theme 定义，语义完全等同）：

| 现有补丁写法 | 回退为 |
|---|---|
| `text-[var(--accent-color)]` | `text-brand` |
| `bg-[var(--accent-color)]` | `bg-brand` |
| `border-[var(--accent-color)]` | `border-brand` |
| `text-[color:var(--accent-color)]` 等变体 | `text-brand` |
| `bg-[var(--accent-color)]/12` 这类（若存在） | `bg-brand/12`（透明度修饰符跟着搬） |

执行方式：逐文件用编辑器替换（先 grep 列出全部命中行，逐个替换后
`grep -c` 验证该文件已清零）。

**边界**：
- `--accent-color` 出现在 `<style>` 块 CSS 里（如 `border-color: var(--accent-color)`）
  是**合法用法，不动**——只回退 class 名里的任意值工具类。
- `components/schedule/` 目录是本项目自建（原版没有对应物），其中的
  `var(--accent-color)` 一律不动。
- `styles/*.css` 里直接用 `var(--accent-color)` 的选择器不动。
- 本项目自建、原版无蓝本的组件（如 InterviewRoomView 等本项目独有页面）里
  出现的补丁，也同样回退（机械替换语义等同，无风险）。
