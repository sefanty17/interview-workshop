# S4 · 前端接剧本驱动（advance 链路）

## 背景

后端剧本引擎已落地（commit `7d96201`），`POST /api/sessions/{id}/advance` 能把剧本推进到下一个
阻塞点（input / 结束），SSE 事件序实测为：
`script:chapter-change → script:progress(0) → script:narration → script:progress(1) →
ai:thinking → ai:reply×2 → status:reset → script:progress(2) → script:input`。

但前端房间（`frontend/src/views/InterviewRoomView.vue`）目前只会走自由对话
`POST /api/sessions/{id}/messages`（`sendToBackend`），剧本模式没有任何 advance 调用。
本规格把剧本模式接上 advance 链路。

## 禁区（违反任一条直接返工）

1. **SSE 事件名一个都不许改、不许自创**。只允许消费这批名字：
   `ai:reply / ai:thinking / status:reset / ai:error / script:narration / script:input /
   script:modify-character / script:chapter-change / script:progress / script:end`。
   出处：`backend/src/main/java/cn/edu/zjut/interview/engine/SseEventSink.java`。
2. 不许跑任何 git 命令（提交归主线）。
3. 不许用裸 `mvn`（本机 Maven 启动链是坏的）。
4. 不许动 `.workbuddy/`、`docs/`、`references/`。
5. 自由对话模式（`mode !== "script"`）的现有行为一行不许变，降级假回复必须保留。
6. 改完必须 `cd frontend && npx vue-tsc --noEmit` 0 error。

## 后端事件 data 的精确形状（照抄，不许改字段名）

- `script:narration` → `{ "text": string }`
- `script:input` → `{ "hint": string }`
- `script:modify-character` → `{ "emotion": string }`
- `script:chapter-change` → `{ "code": string, "name": string }`
- `script:progress` → `{ "chapter": string, "eventIndex": number, "lineCount": number, "vars": object }`
- `script:end` → `{}`（空对象）
- `ai:reply` → 已有 `ReplyEvent`，不动

## 改动 4 · `frontend/src/views/InterviewRoomView.vue`

新增（script 模式专用，free 模式完全不经过）：

1. `const scriptChapter = ref<{ code: string; name: string } | null>(null)`
   `const scriptProgressPct = ref(0)`
   `let scriptBlocked = false`（引擎停在 input 阻塞点）
2. 核心函数 `runAdvance()`：
   - 模式照抄 `sendToBackend` 的「先收 buffered，再统一播放」：
     - `script:narration` → buffered.push({ role:"ai", text: data.text, narration: true, final: true })
     - `ai:reply` → 与 `sendToBackend` 完全相同（ReplyEvent → RoomLine）
     - `script:modify-character` → `roomStore.showCharacterEmotion = data.emotion || "正常"`
     - `script:chapter-change` → `scriptChapter.value = { code: data.code, name: data.name }`
     - `script:progress` → `scriptProgressPct.value = data.lineCount > 0 ? Math.min(100, (data.eventIndex / data.lineCount) * 100) : 0`
     - `script:input` → `scriptBlocked = true`；`roomStore.inputHint = data.hint`
     - `script:end` → `autoFinish.value = true`
     - `ai:error` → `console.warn("[interview] ai:error", ev.data)`
     - `ai:thinking` / `status:reset` → 忽略（播放逻辑统一在流结束后处理）
   - 流结束后：buffered 有内容 → 逐条 `pushMessage("ai", line.text, { emotion: line.emotion })` 入
     session，再从 `roomStore.lines.length` 起逐条 `pushLine`，`roomStore.cursor = first`、
     `roomStore.state = "responding"`（与 `sendToBackend` 尾部一致）。
     buffered 为空且 `scriptBlocked` → `roomStore.state = "input"`。
   - 异常：`catch` 里 `console.warn("[interview] 剧本推进失败", error)`，不发 ai:error 假事件。
3. 挂载（`onMounted`）：`ensureServerSession()` 成功且 `store.session.mode === "script"` 时：
   - 调 `fetchSessionDetail(sessionId)`：
     - `detail.messages`（后端落库的台词）为空且 `eventSequence` 为 0 → 全新场次：清掉本地
       `startSession` 预埋的开场句（`resetRoom()` + `store.session.messages = []`），然后
       `runAdvance()`。
     - 否则是刷新续跑：本地已有的 `syncRoomFromSession()` 结果保留，把后端 messages 里比
       本地多的部分**不重复**（本地为准即可），`scriptBlocked` 视 `detail.eventSequence`
       所处位置无法可靠判断——保守做法：续跑时不自动调 advance，直接
       `roomStore.state = "input"` 让用户接着答（用户发言会触发 advance 续跑，引擎从
       eventSequence 继续，不重放）。
   - free 模式维持现有逻辑（`ensureServerSession` 后直接 return 那段不动）。
4. `handleSend`：`store.session.mode === "script"` 且后端在线时，用户发送后走
   `runAdvance()`（不是 sendMessage）。具体：现有 `sendToBackend(text)` 调用处改为
   `if (store.session.mode === "script" && sessionId.value !== null) { scriptBlocked = false; ok = await runAdvance(); } else { ok = await sendToBackend(text); }`，
   `ok === false` 才落到本地假回复降级。
5. 顶部进度（模板 ③ 区，仅 `isScript` 分支）：后端剧本已连接（`scriptChapter.value !== null`）时，
   `第 X / Y 题` 改为显示 `{{ scriptChapter.name }}`，进度条 `progress` 改绑
   `scriptProgressPct`；离线降级（scriptChapter 为 null）保留原 questionPool 逻辑。
   其余模板不动。
