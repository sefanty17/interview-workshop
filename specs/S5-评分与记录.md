## 改动 1 · 后端评分（`InterviewEngine.finishNow`）

评分规则（写死，不许自创别的）：设该 session 的 user 消息条数为 `n`（0 条也允许结束），
user 消息平均字符长度为 `avgLen`（n=0 时取 0）：

```
score = clamp(60 + min(25, 5 * n) + min(15, avgLen / 40 的整数部分), 0, 100)
```

实现要点：
- 消息从 `dialogueMessageRepository`（先读 `InterviewEngine` 里现有字段名，用它已有的
  Repository，不要新造；查询条件：sessionId + role=user，按现有实体字段写）。
- `session.setScore(score)` 后再 `save`。
- 依赖注入若缺 Repository，在构造器里补（该类已有构造器注入模式，照抄）。

## 改动 2 · `backend/.../dto/SessionFinishView.java`

从 `record SessionFinishView(Long id, String status)` 扩为
`record SessionFinishView(Long id, String status, Integer score)`，
`finishNow` 返回时带上刚算出的 score。所有构造调用点同步（应该只有 finishNow 一处 +
可能的测试）。

## 改动 3 · 后端测试

在 `backend/src/test/java/cn/edu/zjut/interview/` 下（挑一个 engine 相关测试文件或新建
`EngineFinishTest`）：

- 3 条 user 消息、平均 200 字：60 + 15 + 5 = 80。

测试基建照抄现有测试（H2 mem，`application-test.yml`）。

## 改动 5 · `frontend/src/views/InterviewRoomView.vue` 的 `finish()`

在现有 `finish()` 里、构造 `record` 之前：
- `sessionId.value !== null` 时 `await finishSession(sessionId.value)` 拿真分数：
  `record.score` 用后端返回的 score（dimensions 仍用现有 mock 逻辑——真评分只有总分）；
  后端调用失败（catch）→ 走现有 mock 分数路径，行为不变。
- free/script 两种模式都生效。
- 注意 `finish()` 目前是同步函数，改成 async 不影响调用方（`endNow` 已 await confirmDialog，
  watch 里 `finish()` 调用点加不加 await 都行，但不要让 watch 阻塞）。

## 改动 6 · `frontend/src/views/RecordsView.vue`

先读该文件再动手。要求：
1. 挂载时 `isBackendUp()`（已从 `api/chat.ts` 导出）→ 成功则 `fetchSessions("finished")`，
   把后端场次映射成本地 `InterviewRecord` 形状的**只读条目**追加到列表：
   - `id: "s-" + summary.id`（与本地 `r-` 前缀区分）
   - `jobName: summary.title`、`personaName: summary.interviewerCode ?? "-"`、
     `date: summary.endedAt ?? summary.startedAt ?? "-"`、`score: summary.score ?? 0`、
     `dimensions: []`、`questions: []`、`advice: []`
2. 列表渲染：`dimensions` 为空的条目，"成长曲线" 区块跳过它（`records.length >= 2` 的
   计算里过滤掉 `dimensions.length === 0` 的条目）；点击后端条目不路由到 report
   （ReportView 依赖完整 questions），改为弹确认框显示 `title / score / status` 即可，
   用现成的 `confirmDialog(title, message)`（从 `../store/dialogStore` 导入）。
3. 后端不可用 → 完全保持现状（纯本地列表），不加任何报错 UI。
4. 删除后端条目时只从展示列表移除，不调后端（本地条目删除逻辑不动）。
