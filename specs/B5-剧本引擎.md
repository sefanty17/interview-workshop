## 1. 语义映射：Rust 阻塞 → Java 请求边界

LingChat 是进程内长跑：`input` 事件 `rx.await` 挂起等前端。
Java 没有这个上下文，映射为「**推进到下一个阻塞点就返回**」：

| LingChat | 本项目 |
|---|---|
| `script_status.current_chapter_key` | `interview_session.current_chapter` |
| `script_status.current_event_process` | `interview_session.event_sequence` |
| `script_status.vars` | `interview_session.variable_info`（JSON 字符串） |
| `rx.await` 等用户输入 | 引擎跑到 `input` 事件 → 落库 → 推 SSE `event: input` → 返回 |
| 用户提交后继续跑 | 下一次请求从 `event_sequence` 继续 |

`run(session, sink)` 的循环：

```
while (true) {
    chapter = 取 session.currentChapter 对应章节
    if (chapter == null || "end".equals(code)) → 结束，status=finished，推 event: finished，return
    events = 解析 chapter.events 为 JSON 数组
    while (eventSequence < events.length) {
        event = events[eventSequence]
        eventSequence++            // 先自增再执行，与 Rust 的 progress += 1 一致
        落库 current_chapter + event_sequence + variable_info
        if (事件有 condition && !evaluate_condition) → continue（跳过，不产生输出）
        switch (event.type) {
          narration         → 落库旁白行 + 推 event: narration；继续
          ai_dialogue       → 注入剧情提示行 → LLM 流式 → 逐句推 event: reply → 落库；继续
          modify_character  → 推 event: character {emotion}；继续
          chapter_end       → 算出 next → currentChapter = next；eventSequence = 0；落库；break 内层
          input             → 推 event: input {hint}；落库；return（阻塞点）
          free_dialogue     → 见 §5；return（阻塞点）
          default           → 记录日志「未注册事件类型」；继续
        }
    }
}
```

**每执行一个事件都要立刻 `save` session**（`current_chapter` / `event_sequence` / `variable_info`），
保证刷新能续跑且不重放。

## 3. 事件实现（逐个，1:1）

包名统一 `cn.edu.zjut.interview.engine`。

### 3.1 `engine/ConditionEvaluator.java`

照搬 `evaluate_condition`（`events/mod.rs` 186-231）：

- 空串 → `true`
- 先 `split("!=", 2)`：变量未定义 → `true`；否则 `变量字符串 != 值`（值去掉首尾引号）
- 再 `split("==", 2)`：变量未定义 → `false`；否则相等判定
- 都没有：当布尔变量查表，`Bool → 自身`，`Null → false`，其他非 null → `true`，未定义 → `false`
- 变量值取字符串：字符串原样，其他用 `toString()`（用 Jackson `JsonNode.asText()`）

签名：`public static boolean evaluate(String condition, JsonNode vars)`

SSE 事件名 **照搬 LingChat**（`script_engine/responses.rs:13 event_names`），不许自己起名字：

| 本引擎方法 | SSE 事件名 | LingChat 常量 |
|---|---|---|
| `reply` | `ai:reply` | `generator.rs` emit `ai:reply` |
| `narration` | `script:narration` | `SCRIPT_NARRATION` |

| `events/ModifyCharacterEvent.java` | `modify_character` | 读 `characterId` + `emotion`，`sink.character(emotion)`；把 `emotion` 写进 `variable_info.forcedEmotion`；返回 null |

| `events/ChapterEndEvent.java` | `chapter_end` | 见 3.7 |

### 3.7 `events/ChapterEndEvent.java`（照搬 chapter_end_event.rs）

```
endType = event.end_type，缺省 "linear"
linear     → next = event.next ?: event.next_chapter ?: "end"
branching  → 遍历 options[]：condition 为空 或 evaluate_condition 命中 → 取该 option.next，break
             一轮没命中 → 再扫一遍找 default==true 的 option 取 next
             都没有 → "end"
ai_judged  → 必须调 LLM。llmClient 不可用 → 抛异常终止剧本（不回落到默认分支）
             prompt = "{event.prompt}\n\n【对话记录】:\n{最近 N 条消息}\n\n【可选章节】:\n{1. name\n2. name}\n\n请只回复章节名称本身，不要包含其他内容。"
             用 llmClient 非流式补全，trim 后 → matchAiResponseOptions
             仍匹配不到 → 取 options[0].next；options 为空 → "end"
未知 endType → log.warn + "end"
```

`【对话记录】` 取本 session 最近 20 条消息，格式 `{role}: {content}`；为空时写「（无对话记录）」。
这段拼装逻辑原样照搬 `call_llm_for_judgment`，**不要精简**。

## 4. `engine/InterviewEngine.java`

```java
@Service
public class InterviewEngine {
    public InterviewEngine(InterviewSessionRepository sessionRepository,
                           InterviewMessageRepository messageRepository,
                           InterviewChapterRepository chapterRepository,
                           InterviewerRepository interviewerRepository,
                           InterviewScriptRepository scriptRepository,
                           LlmClient llmClient,
                           ObjectMapper objectMapper) { ... }

    /** 从当前进度推进到下一个阻塞点（input / free_dialogue / 结束） */
    public void run(Long sessionId, EventSink sink);

    /** 提交用户输入后继续推进；返回前先把用户消息落库 */
    public void submitAndRun(Long sessionId, String text, EventSink sink);
}
```

要点：

1. `run` 开头读 session；`status != "running"` 直接 `sink.finished()` 返回（幂等）。
2. 章节查询：`chapterRepository.findByScriptIdAndCode(scriptId, code)`；
   若 `findByScriptIdAndCode` 不存在，**在 `InterviewChapterRepository` 里新增**（只增不改）。
3. 切章成功时 `sink.chapter(code, name)`。
4. `current_chapter == "end"` 或章节查不到 → `session.status = "finished"`、`endedAt = now()`、
   `sink.finished()`。
5. 每个事件执行前 `sink.progress(chapterCode, eventIndex, 消息条数, vars)`。
6. 每步 `sessionRepository.save(session)`。
7. 异常：`sink` 推 `event: error` `{"message":"..."}` 后 `emitter.completeWithError` 由 Controller 处理；
   引擎内部只抛异常，Controller 兜底。

`variable_info` 用 `ObjectMapper` 读写 `ObjectNode`，缺省 `{}`。

## 5. `free_dialogue`（照搬 free_dialogue_event.rs）

读 `switch / maxRounds / endLine`：

- 进入：`variable_info.freeDialogue = {"switch": <bool>, "maxRounds": n, "endLine": "...", "used": 0}`，
  `sink.input("")`（让前端进入输入态），主循环 return。
- 之后 `submitAndRun` 时若 `freeDialogue.switch == true`：
  直接走 `ChatService` 的自由对话链路生成回复（不套剧本 prompt），`used++`；
  `used >= maxRounds` 时把 `endLine` 当旁白落库 + `sink.narration(endLine)`，清掉 `freeDialogue`，继续主循环。
- 种子数据当前不用该事件，实现要能跑通单测即可。
