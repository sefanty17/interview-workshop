# A1 · 立绘动效（情绪演出 1:1）

> 主线写规格，子 agent 执行。本批只做**前端立绘演出**，不改对话逻辑、不改后端。

## 0. 问题（已由主线诊断定位，先读现状再动手）

智豪反馈「对话时角色立绘的跳转有点生硬」。四条原因：

1. **情绪动画 CSS 整个没搬**（主因）。原版 `assets/styles/avatar-animation.css`
   （`breathing` 4s / `angryJump` / `suprisedJump` / `heartBeat` / `seriousThink` /
   `happyBounce` / `naughtyBounce` / `embarrassedEmo`）+ `useRoleAvatar` 把
   「当前情绪 → 动画类 / 气泡图 / 音效」算成 `activeAnimationClass`。
   本项目 `GameRoleAvatar.vue:78` 的 `containerClasses` 恒 `{}`；
   `~:75` 设了 `--avatar-breath-scale: 1.0035` 但**全项目没有任何 `@keyframes breathing`**
   → 立绘全程静止。
2. **情绪切图没有真交叉淡入**：`StaticRolePresentation.vue` 是
   `<Transition name="avatar-crossfade">` 包 `v-show` 的 `<img :key="src">`。
   `v-show` 与 enter/leave 语义冲突（元素不移除、`display:none` 盖掉 opacity 过渡）
   → 实际多为瞬切。原版是专用 `ImageAcrossFade`（两图层 300ms）。
3. **槽位宽度无过渡**：`GameRoleAvatar.vue:63` 的 transition 只列了
   `left/top/opacity/filter`，**没有 width**；1 人 ↔ 2 人时槽宽 100%→45% 瞬间跳变。
4. 说话/非说话只有 `brightness(0.78)`，没有情绪动作反馈。

## 2. 改写规则（技术栈差异，逐条照做）

1. **去掉 Tauri**：`invoke(...)`、`convertFileSrc(...)`、`@tauri-apps/api/*` 一律删除。
   立绘 URL 解析改成：按前端现有的立绘路径规则拼
   （先读 `GameRoleAvatar.vue` / `StaticRolePresentation.vue` 现状，沿用它们已有的拼法，
   不要另发明一套路径）。
2. **去掉 i18n**：`useI18n()` / `t(...)` 删掉，文案直接写中文。
3. **store 替换**：原版 `useGameStore`（`currentStatus` 思考态）→ 本项目 `roomStore`；
   原版 `useUIStore`（`bubbleVolume`）→ 本项目若有对应设置字段就用，
   没有就**在本项目 store 里加一个最小字段**（默认 100），别硬编码。
4. **保留原版的"代次号竞态保护"**：`resolveAvatarId` / `latestEmotionId` 两条异步链各自
   推进代次号，只有最新一次能写状态；`handleAnimationEnd` 播完回 `normal`。
5. **保留气泡重播机制**：`showEmotionBubble` 必须
   `置 false → nextTick → 置 true`（连续两次同情绪也要重播）；
   `showThinkingBubble` 不重触发（与重构前一致）。
6. **尊重 `prefers-reduced-motion: reduce`**：duration 归 0。
7. 原版 `ImageAcrossFade` 的 `crossorigin` 降级重试逻辑保留（本项目同源图片不会触发，
   但逻辑照搬）。
8. **CSS 注入**：`avatar-animation.css` 按原版做法是「全局注入」——
   在本项目里挂到 `main.ts` 的样式导入列表（已有 7 个 css，追加到末尾），
   与 V1 加的 `lingchat-globals.css` 相邻。注意原版文件头注释说明：
   同名 `@keyframes breathing` 曾有两份导致幅度不确定，本项目只准有这一份。

## 3. 组件改动

### 3.1 `StaticRolePresentation.vue`
- 用 `ImageAcrossFade` 替换现在的 `<Transition name="avatar-crossfade">` + `v-show` 写法。
  要点：`v-show` 改 `v-if` 语义（由 ImageAcrossFade 内部两层控制显隐），
  `<img>` 不再是"key 变了就瞬切"。
- 保留现有 prop 名（`src` / `visible` / `layerStyle` / `animationClasses` / `objectFit`）
  和 `overlay` 插槽，别改名。
- `defineExpose({ waitForLoad })`：把 ImageAcrossFade 的 `waitForLoad` 透出，
  供 `GameRoleAvatar` 在播放情绪动画前等图就绪（原版 `waitForAvatarLoad` 注入点）。

### 3.2 `GameRoleAvatar.vue`
- `containerClasses` 恒 `{}` → 接 `useRoleAvatar` 的 `activeAnimationClass`
  （形状保持 `Record<string, boolean>`，组件模板里怎么用的就怎么给）。
- `roleLayerStyle` 的 `transition` 字符串补上 `width`
  （与 `left` 同一条缓动曲线：`width 0.5s cubic-bezier(0.25, 0.8, 0.5, 1)`）。
- 接上气泡层（`.bubble` / `.bubble.show` / `.bubble.angry` / `.bubble.happy`
  类名已由 avatar-animation.css 提供）与 `<audio ref>` 元素，
  由 `useRoleAvatar` 的 `isBubbleVisible` / `currentBubbleImageUrl` /
  `currentBubbleClass` 驱动；`playBubbleAudio` 需要 audioRef。
- **不要改** `standardAvatarStyle` 的定位计算逻辑，也不要改现有 prop（`code/emotion/scale/offsetX/offsetY/active`）。

### 3.3 `GameRolesStage.vue`
- 需要把 `emotion` 及一个"情绪版本号"传给 `GameRoleAvatar`
  （原版靠 `role.emotion` + `role.emotionRevision` 双 watch 源驱动演出）。
  若本项目 emotion 变化时组件不会重建，需在 stage 或 roomStore 层补一个
  `emotionRevision`（每次切情绪自增），保证**连续两次相同情绪也能重播动画**。
  具体加在哪一层，先看 `roomStore` 的现状再定；拿不准就在报告里说明你的选择与理由。
